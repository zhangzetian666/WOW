# 新增自动钓鱼需求与实现口径

本次新增范围为自动钓鱼，Windows 工具目标版本 0.7.0，沿用兼容插件 0.5.1。文档规格、开发侧检查和游戏现场验收分别记录；最终结果见 [开发侧验证记录](../verification.md)，操作见 [自动钓鱼指南](../fishing-testing.md)。

## 来源

- 用户提供《魔兽世界无限服自动钓鱼脚本开发产品文档.docx》，包含自动钓鱼的流程、参数、热键和验收设计。

- 产品稿引用的《自动钓鱼脚本需求.docx》及另一个旁证视频未随本次文件提供，没有宣称已经读取或分析。

## 功能闭环

1. 人工保存钓点、朝向和当前 NPC，录制钓点到该 NPC 的同图多点路线，核对地图标定与键位。
2. 到达钓点并确认朝向后，默认短按一次 `1` 投竿，开始本杆 30 秒窗口。投竿键可在界面选择。
3. 仅接收本杆最小等待时间之后的新水花候选。一个候选在一杆内最多触发一次 `F`，去抖后不重复收杆。
4. 只有观察到拾取完成或库存变化，才记录“确认收获”，再等待 1 秒重抛；`F` 没有反馈时保留原 30 秒截止，不连按 `F`。
5. 没有水花则走 30 秒超时重抛分支，不伪造鱼讯或收获。遇到无法确认的施法状态，按实际安全检查结果停止或有界等待。
6. 确认包满时取消当前钓鱼窗口，保存进度，沿录制路线正向返回 NPC。
7. 通过确认的键盘绑定扫描 NPC，完整名称哈希和实时单位身份都匹配后才按 `F`。由用户已有自动售卖插件处理清包，钓鱼模块不点物品、不执行出售动作。
8. 只有同一商人身份及真实库存版本、空位恢复等证据满足，才逆序返回钓点并恢复保存朝向，再开始新的一杆。

游戏动作全部纯键盘。不得加入鼠标输出、点击浮标、点击背包或鼠标寻路。启用有效可逆路线时，初始归位只允许从已记录节点加入逆序剩余路段，到钓点后还原朝向；不把任意出生点或走廊投影当作已验证入口，初始归位不记作售卖成功。

## 识别与状态依据

| 项目 | 本轮口径 |
| --- | --- |
| 水花声音 | 由提供的视频提取单次参考特征；只在当前投竿窗口内形成候选，不把整段拼接录音当一次模板 |
| 系统声音 | 默认播放设备 WASAPI 环回，非麦克风；混音可能包含其他应用及其他玩家声音，匹配分数不等于真实咬钩概率 |
| 音频失效 | 设备失败、默认设备变化、断续或错误时间戳清除旧候选；严格模式停止。连续约 5 秒静音也不当成有效监听 |
| 无声音回退 | 用户明确勾选后，仅允许无鱼讯的 30 秒重抛；没有可用声音时不得触发 `F` 收杆 |
| 包满声音 | 匹配参考角色提示音，不执行通用语音转写 |
| 包满文字 | 仅在客户区顶部中央区域比较暗红提示字形；聊天框同字、空白和普通红块不能作为同一提示，不是通用 OCR |
| 包满融合 | 声音与顶部文字在有界时间内相互确认；已知零空位可作为另一项证据。单独一个候选不能直接认定包满 |
| 收获确认 | 使用只读拾取开关事件或库存变化；收杆尝试次数和确认收获次数分开 |
| 商人确认 | 保存的完整 NPC 名称哈希、当前非玩家友方身份及商店所属单位一致；窗口关闭、超时或按过 `F` 均不代表已清包 |
| 导航 | 复用项目已有地图、朝向标定和记录路线；正向到 NPC，逆向回钓点，不跳点穿越未记录地形 |

参考回放在同一素材中匹配到四个水花候选和一个包满语音候选，属于建模材料的复现，不能作为独立准确率测试。约 130–138ms 仅是参考水花算法窗口，不包含真实设备采集、缓存、调度和按键传输。产品稿提出的端到端 200ms 目标仍待实机测量。

## 人工配置与热键

| 操作 | 默认键或入口 |
| --- | --- |
| 投竿 / 收杆及 NPC 互动 | `1` / `F`，均须先在实际客户端核对；开启 Auto Loot |
| 保存钓点与朝向 | `F5` 或“保存钓点” |
| 开始录路线 / 保存中间路点 / 结束录制 | `F6` / `F7` / `F8` |
| 导出 / 导入路线 | `F9` / `F10` |
| 保存当前 NPC | `F11`，完整名称过长时人工补全并核对哈希 |
| 启动 / 暂停 | `Ctrl+F12`，释放组合键后才进入准备与倒计时 |
| 急停 | `F12`，取消工具拥有的按键；仍需人工处理游戏已经开始的动作 |

全局快捷键默认须显式启用；运行和准备阶段解除配置键注册。`F6` 录制热键可能与所选 NPC 宏键冲突，配置时可以暂关全局快捷键或使用按钮。脚本不自动修改游戏绑定。方向键、Q/E 或 A/D 的实际转向作用以客户端现场标定为准。

## 文件、安全与验收

- 方案和断点使用项目现有严格 JSON，不新增 YAML 或第二套目标数据库。方案保存、导入清除人工确认；导入不启动。地图、路线首点、钓点、可逆性和 NPC 必须一致。
- 断点保存方案指纹、阶段、记录节点及必要的商人身份/原库存基线；恢复要人工确认当前位置。售卖等待断点继续核验同一商人和实际清包证据，不重复按 `F`。旧水花、未释放按键和未完成收杆不能随断点恢复。
- 所有实机启动，包括站桩钓鱼，都要确认当前地图朝向标定。倒计时后逐次核对前台、F12、数据来源新鲜度、地图、候选有效期和键位所有权；用户仍按住 Ctrl、Alt 或 Shift 时停止，不与工具按键组成组合，也不替用户释放修饰键。
- 钓鱼与路线、战斗、完整流程互斥。战斗、死亡、幽灵、地图变化、过期数据和输入故障停止；不能因为钓鱼需求隐式启动打怪或复活。
- 音频和图像由生产路径处理，输入监控只读内存缓存；日志、截图和导出不放在输入监控中。实机监听不保存原始系统音频。
- 日志区分观察、候选、计划按键和已确认结果；自动导出的 `game_validation` 保持 `pending`。日志和关键截图沿用既有有界留存策略。
- 必须分别验证：严格文件边界、30 秒/1 秒定时、单杆单 `F`、旧/重复/未来事件拒绝、包满优先、NPC 身份、原路返回、键盘部分失败释放与模式互斥。
- 实际音频设备、`F` 是否能真实收杆、Auto Loot、售卖插件、UI 缩放、地形、端到端延迟和至少两小时游戏运行均为现场验收项；合成时钟或同素材回放不能替代。
