# 开发需求总表

## 2026-11-17 当前现场补充（覆盖此前“不用测试”的轮次限制）

- 用户现已授权在本机 E 盘真实客户端自行测试，首要目标是点击脚本后自动打怪。
- 预期生产场景为黄名怪区域巡航，主要中断是包满后沿已录商人路线售卖并返回。现阶段不增加装备损坏后自动修理流程；测试开始前先修好装备。
- 重新登录后的本轮验收重点为多轮自动寻怪并击杀，不以单次完整闭环代替连续运行。附近模式脱战只主动锁定反应值4的黄名怪；红名、友好及反应未知目标均不主动开怪，已进入战斗时仍可锁定可验证的攻击者自卫。
- 默认脱战生命低于80%开始吃喝，恢复到满血附近后继续；复活后的首次启动先恢复满血，不得以资源未知或固定等待冒充恢复成功。70%可作为后续可配置值。
- 盗贼能量不是法力，低能量不得触发饮水。现场食物在动作条第12格（=）；原8号食物假设不适用于此角色，9号实际为闪避，不能当饮水键使用。
- 贴近不等于面向；须先验证朝向。遇障碍无位移时应改变方向或停止，不能持续顶墙。
- 新增自动拾取及剥皮：确认本次击杀的同一尸体，等待脱战后拾取，再核对可剥皮状态并按7；仅收到剥皮成功事件才记成功。当前角色已学中级剥皮114/150、有剥皮刀，技能放第7格；此配置须在启动时检查。

- 开发侧自动检查、现场按键、技能施放、目标死亡、拾取和连续运行分别记录。未验收部分不得写成通过。

## 三、目标识别与技能

### 3.1 保存、扫描与接近

- 原需求：选中怪物或NPC后保存名称与头像，用Tab切换附近目标；命中已保存怪物后接近并攻击。
- 当前按完整名称哈希、当前单位身份、可攻击性及非玩家条件识别，不用截断显示名代替完整名称。
- 头像可保存为人工参考；完整流程可明确启用辅助相似度检查，但头像不能替代名称和实时身份，也不是通用OCR。
- 普通严格模式仅在同地图、可靠目标坐标、动作射程和地图标定成立时自动接近；数据不足不能猜目标位置。
- 显式Blind兼容模式允许在不可读战斗数据下进行有界按键尝试，未知仍标未知；它不等于准确定位、已观察到伤害或保证击杀。
- 目标切换、变成玩家、失去身份或死亡时，旧目标的待发动作不得转发给新目标。

### 3.2 通用技能与盗贼方案

| 项目 | 需求/已确认设置 |
| --- | --- |
| 可配置技能键 | 数字1至4，可设置顺序与次数；旧配置继续支持整段循环 |
| 开场与循环 | 每个新锁定目标执行一次开场，再执行独立循环；同目标重新接近不重放开场 |
| 邪恶攻击 | 2 |
| 切割 | 4 |
| 剔骨 | 3，用户已确认 |
| 盗贼开场 | 2→4→2→2→2→3，即242223 |
| 目标未死 | 持续按2，即2222…；死亡后不再发下一拍 |
| 尝试间隔 | 盗贼先用750ms，可改500ms；当前配置允许500至5000ms |

- Blind下，现场记录中的1号是普通攻击开关，应跳过且不消耗技能整拍；全是普攻开关的配置应明确报告错误。CLI以`/startattack`维持普攻，不把普攻当职业技能。
- 到期技能优先于补位移动，短移动需为下一拍留出释放及重新规划时间，避免持续走位饿死技能。
- 应用盗贼方案是显式操作，不自动覆盖载入的原战斗配置；修改后保存，CLI也必须读取这份新配置。
- 按键发送只是尝试。能量、连击点、冷却、朝向与距离由客户端实际判定；当前固定开场不保证六项技能都已成功施放。
- 操作见 [盗贼设置与复测](../rogue-combat-testing.md)。

## 四、路线录制、巡航与返回

- 提供开始录制、保存当前坐标点、结束录制、保存文件与重新载入；转角、障碍前后和必要中间位置可保存多点。
- 区分打怪路线`farm`、跑尸路线`corpse_run`及商人路线`vendor_return`；地图、坐标体系、区域与连接点必须匹配。
- 记录并实测当前地图的轴比例、朝向关系、转速、移动速度及实际转向键；Q/E、A/D或方向键不能按客户端名称盲猜。
- 每轮按最新位置/方向修正，接近路点时缩短脉冲；不能只按录制时的持续时间开环重放。
- 支持明确允许的逆序和循环；卡住、无进展、偏离记录走廊、地图变化、超时或不合法连接时停止或按既有有界策略处理。
- 死亡/包满中断保存原打怪路点；返回后经已录连接恢复原流程，不跳过未知地形或直线穿越障碍。
- 详见 [路线指南](../phase2-testing.md)、[完整流程指南](../complete-testing.md)。

## 五、恢复、拾取与剥皮

- 血量低于配置阈值时尝试8号食物；适用魔法值低于阈值时尝试9号饮水，非魔法资源不能误判为缺蓝。
- 恢复中观察读数达到恢复阈值再继续，缺补给、无进展或超时不应无限等待。
- 严格模式拒绝必要生命/资源未知；显式Blind只可跳过不可读阈值并标注，不能记作实际回血成功。
- 击杀须有连续新帧等有效死亡证据，不能把目标暂时消失或单次异常当作击杀。
- 拾取后按拾取事件判断结果；启用剥皮时需成功证据与等待，失败/超时不能虚报完成。
- 原需求以第二次F剥皮；当前提供独立5号剥皮键，并要求现场验证F交互/拾取。不得假定所有客户端第二次F都能剥皮。
- 详见 [战斗与恢复指南](../phase3-testing.md)。

## 六、死亡、跑尸与复活

- 按当前死亡/幽灵状态及可靠证据确认，停止战斗输入；仅操作已知、可见、可用且归属正确的释放/复活按钮。
- 跑尸使用用户录制路线和客户端给出的真实尸体坐标；不能用死亡时角色位置或猜测墓地点冒充未知尸体位置。
- 接近尸体后仍要核对复活冷却、按钮状态及新帧，确认真实存活，再恢复血量并返回原打怪流程。
- 他人复活邀请、陌生弹窗、未知冷却、路线不可达或跨图应停止/交人工，不能反复盲点。
- 医者方式必须具有可靠医者实际位置及身份；缺失时明确停止并提示人工复活，不能径向乱走或用技能射程冒充交互距离。
- `/wowprobe rez`为只读诊断，不因诊断触发目标改变、移动或交互。

## 七、包满、商人和物品保护

- 背包满提示、总空位与持续新帧分别核对；提示和库存矛盾时等待/停止，不用一条提示直接宣布清包成功。
- 保存NPC完整名称、参考头像及返回路线；通过已核对的F6精确选取宏或配置选择键找商人，F交互须现场确认。
- 核对当前友方非玩家NPC身份、保存名称及商店所属单位；错误NPC、未知商店、提前关闭或超时不能算完成。
- 通用逐格售卖只操作已知、可见、占用明确且有可靠物品元数据的格子；默认只售已知灰色物品。
- 保护任务物品、装备/已装备物品、食物饮水、保留ID及未知物品；其他品质须明确配置，不自动确认售卖弹窗或删除物品。
- 每格售卖须观察对应格为空、新库存版本/空位恢复等证据，其他格变化和重复事件不能替代。
- 外部自动清包模式须明确启用并验证服务器/插件确实清包；按过F、商店关闭或等待时间到均不能代表成功。
- 成功后关闭已确认窗口，按记录路线逆序返回并接回原打怪路点；不是任意位置寻路。

## 八、自动钓鱼

- 保存钓点及面水朝向；需要返商人时，保存NPC及同地图可逆多点路线，先核对标定、键位、自动拾取和售卖插件。
- 默认1键抛竿，开始本杆30秒窗口；本杆有效水花候选最多授权一次F收杆，旧、重复、未来及过期声音不能跨杆复用。
- 观察自身拾取事件或库存变化后才记录收获，等1秒再抛；没有反馈保留原30秒截止，不追加F。
- 无鱼讯走30秒重抛分支；旧施法未结束仅在有界宽限内等待，超限停止，不能靠F或Esc盲取消。
- 使用默认播放设备WASAPI环回，不录麦克风、不保存原始系统录音；设备变化、断续或错误时戳清旧候选。
- 严格音频失效停止；用户明确选择无声音回退后只保留超时重抛，不能凭失效声音收杆。
- 包满采用短语音、客户区顶部固定提示字形和已知零空位的有界组合确认，不把单一候选直接判包满。
- 钓鱼全程纯键盘；只F与商人交互，等已验证的外部插件清包，再凭同一商人与真实库存/空位恢复证据返回，不点击物品格或自行售卖。
- 返回钓点恢复保存朝向后继续；初始归位只从已记录节点加入，不能用任意最近点或走廊投影推定入口。
- 水花相似度不是咬钩概率；固定字形不是通用OCR；参考回放不能证明独立误报率、排除其他玩家水花或端到端200ms目标已达成。
- 实际F收杆、Auto Loot、音频设备、多人声音、UI缩放、外部清包、路线地形与长期运行仍待现场确认，详见 [钓鱼指南](../fishing-testing.md)。

## 九、操作、安全与数据

| 项目 | 统一要求 |
| --- | --- |
| 启动 | 实机绑定/地图标定等人工确认、启动前复核和5秒倒计时；导入不自动启动 |
| 急停 | F12、失焦、过期、地图变化或输入故障取消本工具拥有的按键；游戏已开始动作可能需人工处理 |
| 输入所有权 | 发送/释放匹配，部分失败仍释放并锁存；不能释放用户自己的修饰键或自动重启故障会话 |
| 互斥 | 路线、战斗、完整流程、钓鱼及单次按键模式互斥，新模式准备前停止旧模式 |
| 新鲜度 | 用真实来源时间和持续序号核对，缓存处理不能把旧截图重新变新；监控路径读取有时效内存 |
| 钓鱼配置键 | F5钓点、F6开始路线、F7路点、F8结束、F9导出、F10导入、F11保存NPC；须主动启用 |
| 钓鱼启停 | Ctrl+F12释放组合键后准备/启停；F12急停；运行阶段解除配置热键，处理F6与NPC宏冲突 |
| 配置修改 | 停旧运行、清空相应人工确认；不自动改变客户端实际按键绑定 |
| 能力边界 | 不读写游戏内存、不注入封包、不实现加速/瞬移；依赖已验证的只读数据与受控键鼠 |

## 十、方案、断点、报告与交付

- 配置、路线及断点采用当前严格JSON；完整方案`.wowplan`携带受控清单、相关配置、路线与有效头像，不夹带用户运行断点。
- 导入校验边界、路径、文件完整性和一致性，并清空实机确认；损坏文件不能替换当前有效计划或触发运行。
- 断点绑定完整计划身份和记录位置，恢复需人工核对；修改开场等计划内容后不能继续套用旧断点。空开场保留旧方案兼容。
- 钓鱼断点不恢复旧声音、待发F、旧抛竿时限或未释放按键；商店等待恢复保留原NPC和库存基线，不能重复交互冒充新证据。
- 提供离线演示、只读启动条件检查、配置/运行报告和反馈摘要，分别记录观察、计划动作、发送尝试与确认结果。
- 报告标明版本、来源、配置、停止原因、实际/虚拟耗时及证据。自动报告保留`game_validation=pending`，不代替用户填实机通过。
- 日志和截图有容量/保留期边界；截图不可用保留原因，自有窗口渲染预览不能写成实际桌面捕获或游戏截图。
- 原产品设计中的通用OCR/无插件视觉回退、其他配置/存储方案及性能数值不等于全部已落地。当前具体支持以能力矩阵为准，不虚报架构备选。
- 产品设计的性能建议和真实游戏连续至少2小时目标保留待实测；虚拟两小时不能登记成真实连续运行。
