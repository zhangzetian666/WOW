## 0. 文档说明

### 0.1 编写目的

原始需求描述的是「脚本要做什么」，但没有定义「脚本凭什么判断该做什么」以及「具体按下哪个键、鼠标点哪里」。本文档把这两层补齐：

1. 感知层：脚本如何识别角色死亡、背包已满、目标是谁、怪物是否死亡、坐标与朝向、血量与魔法值。

1. 执行层：每个节点对应的游戏内按键、鼠标定位与点击动作，以及动作执行后的成功判据。

1. 控制层：状态机、路线巡航闭环算法、异常恢复与卡死处理。

### 0.2 架构前置假设

采用 「游戏客户端 + 辅助插件 + 外部脚本」双层解耦 架构，而不是让外部脚本直接读取游戏内存：

- 辅助插件（AddOn）：运行在游戏 Lua 沙箱内，负责读取客户端原生 API（坐标、朝向、血量、目标名、背包空格、死亡状态、错误提示等），并把结果以固定格式输出到屏幕上的状态面板（Status Overlay）。

- 外部脚本：负责屏幕截图、图像/OCR 识别、状态机决策、键鼠模拟、路线文件读写与日志。它只通过「看屏幕」和「发按键」与游戏交互，不注入、不改内存。

- 桥接方式：插件在屏幕固定区域绘制一行状态文本或色块编码；脚本按固定坐标截取该区域并解析。这是把 Lua 沙箱内数据传给外部进程的最稳妥方式（Lua 插件无法自由写文件、无法发网络请求，SavedVariables 只在重载界面时落盘，不能用于实时数据）。设计取舍：需求中「根据插件坐标记录打怪路线」已经隐含了插件坐标这一数据来源。本文档把它明确成一个感知层组件，并定义字段、采样频率与降级方案，避免后续开发把「坐标」当成黑盒。

## 1. 产品概述

### 1.1 产品目标

在无人值守的情况下，让角色在指定区域按录制路线循环完成「巡航 → 选怪 → 接近 → 打怪 → 拾取/剥皮 → 恢复」；当出现死亡或背包已满两类中断事件时，自动执行「释放灵魂 → 跑尸 → 复活」或「返回 NPC → 售卖 → 原路返回」，最终回到打怪巡航，形成可持续的闭环。

### 1.2 系统分层

| 层级 | 组件 | 职责 | 对外接口 |
| --- | --- | --- | --- |
| L1  游戏客户端 | 魔兽世界客户端、按键设置、界面设置 | 提供原生操作与显示 | 屏幕画面、按键绑定 |
| L2  感知层 | 辅助插件  +  屏幕识别模块 | 采集坐标 / 朝向 / 血量 / 目标 / 背包 / 死亡 / 错误提示 | 状态字段表（第  3.1  节）、图像模板库 |
| L3  决策层 | 状态机  +  路线引擎  +  配置管理 | 判定当前状态、选择路线、生成动作序列 | 动作指令、日志、路线文件 |
| L4  执行层 | 键盘模拟  +  鼠标模拟  +  动作校验 | 按键、点击、拖动，并验证结果 | 执行原语（第  4  章） |

### 1.3 核心设计原则

1. 感知优先于动作：任何动作执行前必须有明确的感知依据；动作执行后必须做闭环校验。

1. 键位配置驱动：所有按键不硬编码，统一写在键位配置表，并在启动时与游戏内「按键设置」核对。

1. 一切中断可恢复：每条路线都记录当前路点索引，任何状态切换都能从最近路点续跑。

1. 可急停：全局热键（建议 F12）与脚本面板「停止」按钮随时可中断所有输出，鼠标移入屏幕安全角同样触发暂停。

1. 可回溯：每次状态变化、每次识别置信度、每次键鼠动作写入日志，并保留最近 N 分钟截图。

## 2. 游戏内按键设置与鼠标功能基线

本章是全文的键位基准。脚本的所有动作都引用本章的「逻辑动作名」，再由配置表映射到实际物理按键。开发第一件事不是写代码，而是在游戏里把这些绑定逐项确认一遍。

### 2.3 键位配置一致性自检（启动流程）

1. 脚本读取 keybindings.yaml（逻辑动作名 → 物理键 → 按下时长上限）。

1. 与「游戏内按键设置」逐项比对：可通过读取 WTF/Account/<账号>/bindings-cache.wtf（客户端把绑定缓存在此文件）自动核对，或在首次运行时弹出人工核对清单由开发者勾选。

1. 发现冲突（尤其 INTERACT_WITH_TARGET 未绑定到 F、转向键与平移键互换）→ 阻断启动，在脚本面板高亮提示「请先把『与目标互动』绑定到 F」。

1. 自检通过后做一次「试跑」：依次触发 MOVE_FORWARD、TURN_RIGHT、TARGET_NEAREST_ENEMY，用屏幕位移/目标框变化确认键位真的生效。

### 2.5 屏幕坐标与 UI 元素定位体系

1. 归一化坐标：所有 UI 元素模板以 1920×1080 为基准记录 (x_ratio, y_ratio)；运行时按 实际宽 × x_ratio、实际高 × y_ratio 换算，并叠加 DPI 缩放系数。

1. 锚点相对定位：优先相对屏幕中心或相对已识别的父窗口（如死亡对话框）定位按钮，而不是绝对屏幕坐标，降低分辨率/UI 缩放变化带来的偏移。

1. 模板匹配：预存按钮小图（含文字与边框），用 matchTemplate 求相似度；阈值建议 ≥ 0.82；低于阈值不点击，记录并走 OCR 兜底。

1. 点击前二次校验：移动鼠标到目标位置后先截取该点周边小图，确认仍是目标按钮（颜色/文字一致）再下发点击，避免窗口位置变化时误点到别处。

1. 点击动作参数：按下与抬起分离，间隔 60~120ms 随机；两次点击之间加 150~400ms 随机延时；连续失败 3 次升级为「重新定位模板 → 仍失败则停机报警」。

1. 模板库清单：释放灵魂按钮、复活按钮、NPC 对话框选项、拾取窗口物品行、商人窗口标题、背包格边框、尸体高亮图标、脚本面板的「保存怪物目标 / 保存 NPC 目标 / 开始录像 / 坐标保存 / 关闭录像 / 生成并保存路线 / 导入路线 / 开始 / 停止」按钮。

## 3. 感知层设计：脚本如何「看懂」游戏状态

### 3.1 双通道数据来源与状态字段表

通道 A（主）：插件状态面板。 插件在屏幕左上角固定区域绘制一行或多行状态文本（可用等宽字体、固定颜色块编码提高 OCR 稳定性），外部脚本每 100~200ms 截取该区域解析。

| 字段 | 含义 | 来源  API /  事件 | 用途 |
| --- | --- | --- | --- |
| pos_x , pos_y | 玩家地图坐标  0~1 | GetPlayerMapPosition("player") | 路线录制、巡航闭环 |
| map_id , zone | 当前地图标识 | GetCurrentMapAreaID() / GetRealZoneText() | 防止跨地图套用错误路线 |
| facing | 朝向弧度 | GetPlayerFacing() | 计算转向角  Δθ |
| speed | 当前移动速度 | GetUnitSpeed("player") | 估算到点时间、卡住判定 |
| hp_pct , mp_pct | 血量 / 魔法百分比 | UnitHealth / UnitHealthMax 、 UnitPower / UnitPowerMax | 自动恢复 |
| in_combat | 是否战斗中 | InCombatLockdown() / PLAYER_REGEN_DISABLED | 决定能否坐下吃喝 |
| target_name , target_type | 当前目标名称 / 类型 | UnitName("target") | 与保存目标库比对 |
| target_hp_pct | 目标血量 | UnitHealth("target") | 判断怪物是否死亡 |
| target_is_dead | 目标是否已死亡 | UnitIsDead("target") | 拾取 / 剥皮触发 |
| is_dead | 玩家是否死亡 | UnitIsDead("player") / PLAYER_DEAD | 死亡识别主信号 |
| free_slots | 背包总空格数 | GetContainerNumSlots + GetContainerItemInfo 遍历统计 | 包满辅判据 |
| last_error | 最近一条红色错误文本 | UI_ERROR_MESSAGE | 包满主判据、脱困 |
| loot_open | 拾取窗口是否打开 | LOOT_OPENED / LOOT_CLOSED | 拾取流程判据 |
| merchant_open | 商人窗口是否打开 | MERCHANT_SHOW / MERCHANT_CLOSED | 售卖流程判据 |
| corpse_x , corpse_y | 尸体坐标 | GetCorpseMapPosition() | 跑尸终点 |
| ts | 时间戳 | 插件时钟 | 判数据是否过期（超过  500ms  视为失效） |

通道 B（辅）：屏幕图像识别。 用于插件字段不足以覆盖的场景：目标头像/名称、对话框按钮、红字提示、尸体高亮、拾取窗口物品行、背包格图标、血条像素比例。

通道融合规则：主判据与辅判据采用「或 / 与」组合并在防抖窗口内投票。任何一路数据过期或置信度低于阈值时，不触发状态跃迁，只记录告警。

### 3.2 角色死亡识别（需求重点 1）

死亡是全流程里最需要防误判的状态：一旦误判，脚本会在角色活着的时候去点「释放灵魂」，造成不可挽回的中断。

| 序号 | 感知信号 | 采集方式 | 可靠性 |
| --- | --- | --- | --- |
| D1 | 插件字段 is_dead = true （ UnitIsDead("player") / PLAYER_DEAD ） | Overlay  解析 | 高（主判据） |
| D2 | 屏幕中央出现「释放灵魂  /  你已死亡」对话框 | 模板匹配  + OCR | 高 |
| D3 | 画面整体去色 / 灰屏、角色血条为  0 、头像变灰 | 色彩直方图  +  血条像素比例 | 中 |
| D4 | 动作条技能图标全部不可用、无法移动 | 图标灰度模板 | 中 |
| D5 | hp_pct = 0 且连续多个采样周期不变 | Overlay | 中 |

判定规则（建议默认值，可配置）：

1. 满足 D1 或 D2，并且 D3/D4/D5 中至少一项成立；

1. 上述组合需在连续 2~3 个采样周期（约 400~600ms）内稳定成立；

1. 进入死亡状态后写入死亡快照：死亡前最后一个有效坐标、当前路线文件、当前路点索引、死亡时间、当时目标名；

1. 排除项：插件字段时间戳过期、节日/过场黑白滤镜（此时 D1 为 false 且 D2 不出现）、窗口失焦导致的截图黑屏 → 一律不判死亡，只记告警。

为什么不用单一信号：灰屏也可能来自客户端特效或插件故意的黑白滤镜；单看血条 0 可能在加载/掉线瞬间出现。多信号 + 防抖是这里唯一稳妥的做法。

### 3.3 背包已满识别（需求重点 2）

需求原文写的是「游戏提示你的背包已满，无法拾取物品时」。这条提示在客户端里来自 UI_ERROR_MESSAGE 事件，对应 ERR_INV_FULL（Inventory is full / 你的背包已满）等全局字符串，显示为屏幕上方中部的红字；同类还有 ERR_BAG_FULL（某个包满）与 ERR_ITEM_MAX_COUNT（唯一物品/堆叠上限）。

| 判据 | 采集方式 | 说明 |
| --- | --- | --- |
| B1 （主） | 插件 last_error   字段或屏幕上方中部红字  OCR | 匹配关键词：背包已满、无法拾取、 Inventory is full 、该物品无法拾取 |
| B2 （辅） | 插件 free_slots = 0 | 遍历  0~4  号容器   GetContainerNumSlots 与 GetContainerItemInfo 统计空格 |
| B3 （辅） | 连续  2  次拾取动作后   loot_open   仍为  true  且物品行未减少 | 说明物品确实拿不进来 |
| 排除项 | ERR_ITEM_MAX_COUNT / ERR_BAG_FULL （专项包满） | 单独出现不触发返程，只记录并跳过该物品 |

判定规则：B1 命中 且（B2 或 B3 成立），在 3 秒去重窗口内只触发一次；触发后立即执行：

1. 停止 TARGET_NEAREST_ENEMY 与技能序列；

1. 关闭拾取窗口（CLOSE_WINDOW 或点击窗口关闭按钮）；

1. 保存当前路点索引与打怪路线文件句柄；

1. 状态跃迁到 BAG_FULL → RETURN_NPC。

实现提示：UI_ERROR_MESSAGE 的 errorType 是数字索引且随版本变动，不要按索引判断，一律按消息文本/全局字符串匹配；中文客户端按中文关键词匹配，英文客户端按 ERR_INV_FULL 常量匹配，配置里放两套关键词表。

### 3.4 怪物 / NPC 目标识别

| 对象 | 保存内容 | 保存时的键鼠动作 | 运行时的比对方式 |
| --- | --- | --- | --- |
| 怪物目标 | 名称、头像模板、模型特征图、单位类型、保存时间、来源截图 | 游戏中鼠标左键选中怪物  →  鼠标左键点击脚本面板「保存怪物目标」按钮 | 优先比 target_name （ Overlay  精确文本） →  再用头像模板相似度  ≥ 0.85  兜底 |
| NPC  目标 | 名称、头像模板、 NPC  类型、坐标 | 游戏中鼠标左键点击  NPC  头像  →  点击脚本面板「保存  NPC  目标」按钮 | 同上；额外校验 target_type   为友好 / 中立且可交互 |

Tab 扫描的判定逻辑：按一次 TARGET_NEAREST_ENEMY → 等待 150~250ms → 读取 target_name → 与保存库比对 → 命中则进入接近/战斗；未命中则继续按 Tab，最多扫描 N 次（建议 8~12 次，覆盖视野内目标数），一轮扫完无命中则继续沿路线走到下一路点再扫。单纯靠图像比对目标头像会受血量、光效、缩放影响；UnitName("target") 是最稳的通道，图像模板只作为插件未加载时的降级方案。

### 3.5 怪物死亡、可拾取与可剥皮识别

| 状态 | 感知信号 | 说明 |
| --- | --- | --- |
| 怪物死亡 | target_hp_pct = 0 / target_is_dead = true  /  目标框消失或变灰  /  战斗标志解除 | 需连续  2  个周期确认，避免技能读条瞬间误判 |
| 出现可拾取尸体 | 尸体高亮轮廓、鼠标指针变为「拾取」图标、 LOOT_OPENED 事件 | 决定是否执行拾取动作 |
| 拾取完成 | loot_open = false 且拾取窗口模板消失 | 进入剥皮或继续  Tab |
| 可剥皮 | 指针变为「剥皮刀」图标  /  插件标记尸体可剥皮  /  目标名带「可剥皮」提示 | 决定是否执行第二次  F  或剥皮技能键 |
| 剥皮完成 | 施法进度条结束  + 1.5s  等待  +  出现战利品窗口或尸体图标变化 | 见  6.3.7 |

### 3.6 血量与魔法值识别

- 主通道：Overlay 的 hp_pct、mp_pct；辅助通道：玩家框血条/蓝条的彩色像素长度占比（用于插件未加载时）。

- 触发：hp_pct < 配置阈值HP（默认 40%）且 in_combat = false → 按 HEAL_MACRO（8）；mp_pct < 配置阈值MP（默认 35%）→ 按 MANA_MACRO（9）。

- 恢复期：保持坐下状态，每 500ms 采样一次，直到 hp_pct ≥ 85% 且 mp_pct ≥ 85%，或超过 REST_TIMEOUT（默认 25s）后强制起立继续，避免食物不足时无限等待。

- 战斗中：in_combat = true 时不触发吃喝；若战斗中被打到阈值以下，先完成当前目标或脱战后再恢复。

### 3.7 坐标与朝向识别

坐标是路线录制与巡航的基础，详见 5.1。此处只强调三点：

1. GetPlayerMapPosition 返回的是当前地图内的 0~1 比例坐标，不是世界坐标；进入新区域后必须先 SetMapToCurrentZone()，否则可能返回 (0, 0)。

1. (0, 0) 是合法坐标也可能是无效信号，必须结合 map_id/zone 与时间戳判断：连续多次为 0 且区域未变 → 视为「坐标服务异常」，暂停巡航并报警。

1. GetPlayerFacing 的零点与增减方向在不同版本存在差异，上线前必须做一次标定：角色面朝正北记录 facing，按 TURN_RIGHT 1 秒再记录，得出角速度 ω 与符号，写入配置。

## 5. 路线巡航系统（重点章节）

本章回答用户最关心的问题：路线巡航到底是怎么靠键盘（和鼠标）跑出来的。 结论先行：游戏没有「点击地面自动走到坐标」这类指令，外部脚本也无法直接给角色下发「移动到 (x, y)」。巡航只能靠 「持续按住 W 前进 + 不断修正朝向」 实现，而「修正朝向」有三种可行手段：转向键脉冲、鼠标右键拖动镜头、两者组合。脚本每 100~200ms 读一次坐标与朝向，和目标路点做比较，形成闭环控制；这就是路线巡航的全部原理。

### 5.1 坐标体系与插件接口

| 项目 | 定义 |
| --- | --- |
| 坐标格式 | GetPlayerMapPosition("player") 返回 (posX, posY) ，均为  0~1 ，相对当前地图（ WorldMapDetailFrame ） |
| 地图标识 | map_id + zone （ GetRealZoneText() ），路线文件必须绑定地图，跨图自动失效 |
| 朝向 | GetPlayerFacing() 返回弧度；需实机标定零点与符号 |
| 距离 | 用归一化欧氏距离 sqrt((x−xt)² + (y−yt)²) ；到点容差建议  0.002~0.004 （换算成码需按地图标定） |
| 刷新前置 | 每次进入新区域调用 SetMapToCurrentZone() ；坐标长时间为  (0,0)  视为异常 |
| 采样周期 | 100~200ms （ Overlay  解析成本远高于截图，建议插件字段用像素编码降低  OCR  开销） |
| 版本差异 | 8.0.1  后   GetCorpseMapPosition 迁移到 C_DeathInfo.GetCorpseMapPosition ； 12.0  起部分单位  API  返回  secret  值，直接比较会报错，需走插件侧安全封装 |

### 5.2 路线录制流程（对应需求第 3、4、5 项）

录制是纯人工引导 + 脚本打卡，键鼠分工如下：

| 步骤 | 人 / 脚本动作 | 键鼠实现 |
| --- | --- | --- |
| 1 | 点击脚本面板「开始录像」 | template_click(btn_record_start) ，左键 |
| 2 | 玩家用键盘把角色移动到打怪区起点 | W /  转向键  /  鼠标右键拖动（人工） |
| 3 | 点击「坐标保存」打卡一次 | template_click(btn_save_waypoint)  →  插件采集   (pos_x, pos_y, facing, map_id, ts) 写入临时点集 |
| 4 | 沿预期路线继续跑，遇到拐弯、坡道、障碍物前后各打一次卡 | 重复步骤  2~3 ， 打卡点越密越能绕开地形 |
| 5 | 点击「关闭录像」 | template_click(btn_record_stop) |
| 6 | 点击「生成并保存 / 导出路线文件」 | template_click(btn_export_route)  →  写  JSON |
| 7 | 需要时点击「导入路线文件」 | template_click(btn_import_route)  →  校验地图与点集 |

录制约束：相邻两点距离不宜过大（建议 ≤ 0.01 归一化），否则脚本会用直线连接两点从而撞墙；拐角处必须有点；路线首尾点建议留 1~2 秒 wait 便于扫描目标。

  "route_type": "farm | corpse_run | vendor_return",
  "map_id": 141,

字段说明：route_type 决定路线用途（打怪 / 跑尸 / 返回 NPC）；reverse_policy 为 allowed 时支持逆序回放（包满售卖后原路返回）；action 定义到点后的附加动作（扫描目标、转向点、等待、交互）。

### 5.4 巡航闭环算法（核心）

#### 5.4.1 总体控制回路

```text
读取状态 (pos_x, pos_y, facing, speed)
  → 取当前目标路点 P[i]
  → 计算距离 d 与方位角 θ_target
  → 若 d ≤ tol：判定到点 → 执行 action → i++ → 继续
  → 若 |Δθ| > 转向阈值：松开 W → 执行转向修正 → 重新采样
  → 若 |Δθ| ≤ 转向阈值：按住 W（或 AUTO_RUN）前进一个采样周期
  → 卡住检测 / 事件打断 / 到点判定
  → 回到循环开始
```

#### 5.4.2 方位角计算

令当前位置 (x, y)、目标路点 (xt, yt)：

- dx = xt − x，dy = yt − y

- θ_target = atan2(dx, dy)（WoW 地图 y 轴向下、北为 0；符号与零点必须按 3.7 节实机标定）

- Δθ = normalize(θ_target − facing)，规范化到 [−π, π]

- Δθ > 0 → 右转；Δθ < 0 → 左转

#### 5.4.3 三种转向实现对比（关键设计决策）

| 方案 | 键鼠动作 | 标定参数 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- | --- |
| A.  转向键脉冲 | 松开  W →  key_hold(TURN_LEFT/RIGHT, t)  →  重新采样 | 角速度  ω （ rad/s ），实测获得； t = Δθ绝对值 / ω ，单次上限  400ms ，分多次脉冲防过冲 | 不占用鼠标、不依赖镜头设置、实现简单 | 转向速度受帧率影响，需反复闭环修正 | 默认方案 |
| B.  鼠标右键拖动 | 右键  down →  水平相对位移   Δpx = Δθ绝对值 / k  →  右键  up | 灵敏度  k （ rad/px ），由「拖  100px  实测转过多少弧度」标定 | 转角大、一次到位、不占用键盘转向键 | 依赖镜头灵敏度 /UI  缩放；会同时改变视角，模板匹配需重新定位 | 大角度转弯、 A  方案失效时 |
| C.  平移  +  转向组合 | A/D   平移做横向微调，小角度用  Q/E  修正 | 平移速度、格宽 | 绕小障碍不丢朝向 | 控制复杂度高 | 障碍绕行、贴边修正 |

推荐组合：|Δθ| > 0.6 rad 用方案 B 一次大幅转向；|Δθ| ≤ 0.6 rad 用方案 A 脉冲微调；每轮修正后必须重新采样 facing 再决定是否前进，绝不允许「一次算完一路按到底」。

#### 5.4.4 前进方式

| 方式 | 键鼠动作 | 使用时机 |
| --- | --- | --- |
| hold_w （默认） | key_down(MOVE_FORWARD) 持续一个采样周期，转向时先 key_up | 绝大多数路段，可控性最好 |
| auto_run | key_tap(AUTO_RUN)   开启  Num Lock  自动奔跑；到点前再按一次关闭 | 长直线段，减少长按； 必须处理关闭失败的兜底：按 S 或反向键强制打断 |
| mouse_middle | 中键触发自动奔跑（部分客户端默认） | 备选 |
| 减速接近 | 距目标  < 2×tol  时把  W  改成  100ms  短脉冲 | 防止冲过点后来回震荡 |

#### 5.4.5 巡航伪代码

```python
def cruise(route, start_index=0):
    i = start_index
    stuck_ticks = 0
    last_pos = read_state().pos
    while i < len(route.points):
        st = read_state()                       # 插件 Overlay：坐标/朝向/血量/事件
        if emergency_stop() or st.is_dead or st.bag_full:
            save_checkpoint(route.route_id, i)  # 保存断点，供恢复后续跑
            return interrupted(st)
        target = route.points[i]
        d = distance(st.pos, target)
        if d <= target.tol and stable_frames(d, n=2):
            run_action(target.action)           # scan / wait / interact
            i += 1
            continue
        dtheta = normalize(bearing(st.pos, target) - st.facing)
        if abs(dtheta) > ANGLE_TOL:             # 建议 0.12 rad
            key_up(MOVE_FORWARD)
            turn(dtheta)                        # 方案 A/B 组合，见 5.4.3
            continue
        key_down(MOVE_FORWARD)
        sleep(sample_interval_with_jitter())    # 100~200ms + 随机抖动
        key_up(MOVE_FORWARD)
        moved = distance(st.pos, read_state().pos)
        stuck_ticks = stuck_ticks + 1 if moved < STUCK_EPS else 0
        if stuck_ticks > STUCK_LIMIT:
            recover_from_stuck()                # 见 5.4.6
            stuck_ticks = 0
    return finished
```

#### 5.4.6 卡住与地形阻挡处理

1. 检测：连续 6~10 个采样周期位移小于 STUCK_EPS，或坐标反复在同一区间震荡。

1. 一级恢复：key_tap(JUMP)（Space）+ 短暂 MOVE_FORWARD；常被小台阶/石块卡住时有效。

1. 二级恢复：向侧方 STRAFE_LEFT/RIGHT 300~500ms，配合 TURN_* 小幅转向绕过障碍，再重算方位角（不改目标路点）。

1. 三级恢复：回退到上一个已到达路点 i−1，从该点重新逼近；仍失败则跳过当前路点（记录告警）。

1. 终止：同一路点连续 3 次三级恢复失败 → 停机、截图、日志告警，等待人工处理。

1. 预防：这正是需求里要求「多次点击坐标保存、记录多个打卡点」的原因——路线点越密，脚本越不需要直线穿越地形。开发时应在录制界面提示「拐弯处请务必打卡」。

#### 5.4.7 逆序回放

reverse_policy = allowed 时，把 points 倒序后再执行同一套 cruise 算法。用于「到 NPC 售卖完成后原路返回打怪区」，也用于「跑尸路线」在某些场景的回程。倒序时 action 中的 interact 类动作应过滤掉，只保留 scan/wait。

#### 5.4.8 巡航中的战斗打断与恢复

- 每个采样周期（或每 2~3 个周期）穿插一次 TARGET_NEAREST_ENEMY（Tab）+ 目标名比对；命中保存目标 → 保存当前路点索引 i → 状态切到 APPROACH/COMBAT → 巡航暂停。

- 战斗结束（怪物死亡 + 拾取/剥皮完成）→ 回到 i 对应路点继续执行；若角色已偏离路线超过阈值，先跑回最近路点再继续。

- 血/蓝过低 → 优先 REST，恢复后回到 i。

#### 5.4.9 为什么必须闭环而不能「按录制时的时间重放」

录制时只能保存坐标，无法保证重放时的移动速度、帧率、地形、其他玩家阻挡、被怪攻击导致的减速完全一致。开环重放（例如「W 按 3 秒、右转 0.5 秒」）误差会累积，几十秒后就会完全偏离路线。只有「每周期读坐标 → 算偏差 → 修正朝向 → 再前进」的闭环，才能让角色稳定贴合路点序列。这是本章最重要的工程结论。

### 5.5 三条路线的分工与切换

| 路线类型 | 录制内容 | 起止点 | 触发时机 | 结束后去向 |
| --- | --- | --- | --- | --- |
| farm 打怪巡航 | 打怪区多点闭环 | 打怪区首尾 | 常态运行 | 循环自身 |
| corpse_run 跑尸 | 墓地 / 释放灵魂点  →  尸体（复活位置） | 释放灵魂点  →  尸体 | is_dead 且已释放灵魂 | 复活成功  →  回   farm 最近路点 |
| vendor_return   返回  NPC | 打怪区  →  沿途打卡点  → NPC  位置 | 打怪区  → NPC | 包满判定成立 | 售卖完成  →  逆序回   farm |

需求第 4 项提到「根据释放灵魂的坐标和复活位置的坐标记录后，关闭录像」：这里的两个关键坐标应明确为① 释放灵魂后角色出现的墓地/灵魂医者坐标（跑尸路线起点）与 ② 尸体所在坐标（跑尸路线终点，可由 GetCorpseMapPosition() 自动获取或用死亡快照近似）。脚本导入路线后按 5.4 的闭环跑回尸体附近，再执行 6.3.6 的复活动作。

## 6. 状态机与全流程节点实现

### 6.1 状态枚举与优先级

IDLE、CRUISE（巡航）、TARGET_SCAN（Tab 扫描）、APPROACH（接近目标）、COMBAT（技能序列）、LOOT（拾取）、SKIN（剥皮）、REST（吃喝恢复）、DEAD（死亡确认）、RELEASE（释放灵魂）、CORPSE_RUN（跑尸）、RESURRECT（复活）、BAG_FULL（包满）、RETURN_NPC（返回 NPC）、VENDOR_SELL（售卖）、RETURN_FARM（原路返回）、ERROR（停机）、PAUSED（急停）。

优先级：PAUSED > ERROR > DEAD/RELEASE/CORPSE_RUN/RESURRECT > BAG_FULL/RETURN_NPC/VENDOR_SELL/RETURN_FARM > REST > COMBAT/LOOT/SKIN > CRUISE/TARGET_SCAN。高优先级状态可打断低优先级状态，且必须先保存断点。

### 6.3 关键流程详解

#### 6.3.1 目标保存

游戏中先用鼠标左键选中怪物（或点击 NPC 头像）→ 脚本面板点击「保存怪物目标 / 保存 NPC 目标」按钮。脚本此时做三件事：截图目标框区域生成头像模板、读取 Overlay 的 target_name 精确文本、把 {name, avatar_template, type, ts, source_screenshot} 写入 targets.db。运行时以名称精确匹配为主、头像相似度为辅。

#### 6.3.2 TAB 切换与接近怪物

按一次 Tab → 等 150~250ms（等待客户端刷新目标框）→ 读取目标名 → 命中则进入 APPROACH。接近阶段复用 5.4 的闭环算法，只是把「目标路点」换成「目标当前位置」：由插件输出目标相对方位/距离，或用「面朝目标 + W 前进 + 距离判据」简化实现。到达技能范围后停止 W，进入 COMBAT。

#### 6.3.3 技能释放序列

配置 skill_sequence = "112" 或 "14111"，循环执行 key_tap(SKILL_n)，每次间隔按 GCD/公共冷却配置（默认 1.2~1.6s，带随机抖动）。每轮检查 target_hp_pct 与 target_is_dead：目标死亡立即停止序列；某键位技能未就绪（图标灰）则跳过并记录，下一轮重试。血量/蓝量过低时按优先级插入 REST。

#### 6.3.4 自动恢复

hp_pct < 阈值HP → key_tap(8)；mp_pct < 阈值MP → key_tap(9)。宏内容建议为「/sit + /use 食物/水」，见附录 B。恢复期间每 500ms 采样，超过 REST_TIMEOUT 强制起立，避免补给耗尽时死锁。战斗中不触发。

#### 6.3.5 死亡 → 点击「释放灵魂」（用户重点）

这是需求里没有写清、但开发必须定义清楚的节点：

1. 识别：按 3.2 判定 DEAD，停止全部键鼠输出并写死亡快照。

1. 定位按钮：死亡后客户端在屏幕中央弹出对话框，含「释放灵魂」按钮。脚本用模板库中的按钮小图做匹配（相似度 ≥ 0.82），得到像素中心；若模板失败，用「对话框窗口锚点 + 按钮相对偏移」计算，并叠加归一化坐标兜底值（以 1920×1080 为基准记录）。

1. 点击：mouse_move_ratio → 截取该点周边小图二次校验按钮文字/颜色 → 左键 down/up（间隔 60~120ms）。

1. 备选通道：若 2 次点击后对话框仍在，改用游戏内宏键触发 /script RepopMe()；宏必须预先绑定到某个未占用键位并在配置里登记。

1. 成功判据：对话框消失，且 is_dead 仍为 true 但角色坐标发生明显跳变（出现在墓地/灵魂医者处），或 Overlay 的 zone/pos 与死亡快照明显不同。

1. 失败处理：连续 3 次失败 → 截图、写日志、进入 ERROR 停机，避免反复点击误触其他按钮。

1. 注意：部分客户端在死亡后有强制等待时间，GetReleaseTimeRemaining() 可用于判断是否需先等待；被其他玩家复活时会出现复活邀请对话框，应先按配置决定 AcceptResurrect() 或 DeclineResurrect()，不要盲目点「释放灵魂」。

#### 6.3.6 跑尸与复活（用户重点）

1. 释放灵魂成功后，加载 corpse_run 路线，起点为墓地/释放灵魂点，终点为尸体位置（优先用 GetCorpseMapPosition()，插件未加载时用死亡快照的最后坐标近似）。

1. 以 5.4 的闭环巡航跑到终点容差范围内；途中不执行 Tab 扫描（灵魂状态无意义）。

1. 到达后检测「复活」按钮是否可用（模板匹配 + GetCorpseRecoveryDelay() 冷却判断）。

1. 点击「复活」按钮（左键，流程与 6.3.5 相同），或触发 /script RetrieveCorpse() 宏备选。

1. 成功判据：复活对话框消失、灰屏/去色消失、hp_pct > 0、is_dead = false。

1. 复活后先做一次 REST（复活血量通常很低），再从死亡快照里保存的 farm 路点索引续跑打怪路线；若复活点与打怪区相距较远，可复用 vendor_return 路线的逆序或专门录制一条「复活点 → 打怪区」路线。

#### 6.3.7 拾取与剥皮

- 拾取：怪物死亡后保持目标选中尸体 → 按 INTERACT_WITH_TARGET(F)；若开启自动拾取，物品会直接进入背包；未开启则脚本需按拾取窗口物品行模板逐行左键点击（或 Shift+左键）。成功判据为 loot_open 由 true 变 false、尸体高亮消失。

- 剥皮（勾选时）：需求描述为「第一次 F 拾取 → 第二次 F 剥皮 → 等待 1.5 秒 → 继续 TAB」。实现上要补两点：

1. F 键冲突：INTERACT_WITH_TARGET 对尸体通常只产生拾取；第二次 F 能否触发剥皮取决于客户端版本与「交互」逻辑。因此建议双通道：首选把「剥皮」技能绑到独立键 SKIN_KEY（建议 5），选中尸体后按该键；若坚持沿用需求原文的「第二次 F」，则必须在验收阶段实机验证，并在失败时自动切到 SKIN_KEY 通道。

1. 可剥皮判定：先检测鼠标指针是否变为剥皮图标 / 插件是否输出可剥皮标记；不可剥皮直接跳过，避免空按与 1.5s 无谓等待。

- 等待：第二次动作后等待 SKIN_WAIT_MS = 1500（可配置），期间检测施法进度条；结束后再按 TARGET_NEAREST_ENEMY(Tab) 重新扫描，回到 N05。

#### 6.3.8 包满 → 返回 NPC 售卖（用户重点）

1. 3.3 判定成立 → 停止打怪、关闭拾取窗口、保存 farm 路点索引。

1. 加载 vendor_return 路线，按 5.4 闭环跑回 NPC（需求特别强调不能直线跑：路线文件里多个打卡点会引导角色逐点移动，绕开地形阻挡）。

1. 到达 NPC 附近后按 TARGET_NEAREST_ENEMY(Tab) 或 Ctrl+Tab 逐个切换目标，与 NPC 目标库比对；命中后按 INTERACT_WITH_TARGET(F) 打开对话/商人窗口（兜底：鼠标右键点击 NPC 模型）。

1. merchant_open = true 后，按 OPEN_ALL_BAGS(B) 打开背包；脚本按 Overlay 提供的物品品质/格子信息（或图标模板）筛选待售物品（默认灰色垃圾物品，可配置白/绿装规则），对每个目标格计算 bag_slot_ratio(bag, slot) 并右键单击完成售卖；每卖一格校验 free_slots 是否增加。

1. 售卖完成 → CLOSE_WINDOW(Esc) 关闭窗口 → 按 5.4.7 逆序回放 vendor_return 回到打怪区 → 从保存的路点索引恢复 CRUISE。

1. 若 free_slots 未恢复到阈值（例如有不可售卖的绑定物品），记录告警并可选择继续打怪（下次包满更快触发）或停机等待人工处理。

#### 6.3.9 一个完整循环的时序

CRUISE → N05 命中目标 → APPROACH → COMBAT（技能序列） → 怪物死亡 → LOOT → SKIN → 回 CRUISE → 途中 hp/mp 低则 REST → 若包满则 BAG_FULL → RETURN_NPC → VENDOR_SELL → RETURN_FARM → 回 CRUISE → 若死亡则 DEAD → RELEASE → CORPSE_RUN → RESURRECT → REST → 回 CRUISE。

## 8. 异常、安全与风控

### 8.1 异常分类与处理

| 异常 | 检测 | 处理 |
| --- | --- | --- |
| 掉线 / 返回角色选择界面 | 登录界面模板 /Overlay  数据超时 | 停止输出、停机告警 |
| 窗口失焦 | 前台窗口句柄变化 | 立即释放所有按键并暂停，回焦后人工确认恢复 |
| 分辨率 /UI  缩放变化 | 截图尺寸与基准不符 | 重算归一化换算系数；模板匹配失败则停机提示重新标定 |
| 插件未加载  / Overlay  超时 | ts   超过  500ms  未更新 | 降级到纯屏幕识别；仍不可用则停机 |
| 坐标持续  (0,0) | 3.7  规则 | 暂停巡航，提示打开一次世界地图或重载插件 |
| 跨地图 | map_id 与路线不一致 | 拒绝执行该路线，等待人工确认 |
| 被其他玩家攻击  / PVP | in_combat 异常、目标为玩家 | 按配置选择停机或反击，默认停机 |
| 被  GM  询问  /  出现密语窗口 | 聊天框模板 / 声音提示 | 立即急停并告警，禁止自动回复 |
| 识别置信度低 | 相似度  <  阈值 | 不点击、不跃迁状态，记录并重试 |
| 连续动作校验失败 | 4.3  重试耗尽 | 升级通道  →  仍失败则   ERROR 停机 |
| 自动奔跑关不掉 | Num Lock  状态与位移不符 | 按  S /  反向转向键强制打断，再复位 |

### 8.2 急停与人工接管

- 全局热键 F12（可配置）：立即 key_up 所有按住键、清空动作队列、状态置 PAUSED。

- 脚本面板「停止」按钮：左键点击即停。

- 鼠标移入屏幕左上角安全区（如 60×60 像素）：自动暂停。

- 恢复必须人工确认，避免无人值守下自动重启造成更大偏离。

### 8.3 输入节奏与风险提示

- 所有周期、间隔、按下时长加入可控随机抖动；禁止完全固定周期的机械式输入。

- 不提供内存读写、封包、加速、瞬移类实现；所有移动都通过正常键位与闭环控制完成。

- 合规风险：自动化脚本在多数商业网络游戏中违反服务条款。本文档仅面向自有/授权私服的功能设计与学习研究，部署前请确认目标服务器规则，并自行承担账号风险。

### 8.4 需求原文与实现的差异登记

| 需求原文 | 潜在问题 | 本文档的补充设计 |
| --- | --- | --- |
