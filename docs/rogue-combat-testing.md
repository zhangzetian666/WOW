# 盗贼打怪技能设置与复测

适用Windows工具0.7.1，插件沿用0.5.1。修复依据、验证和待测项目见 [本轮问题记录](recorded-issues-2026-11-17.md) 与 [验证记录](verification.md)。不要只复制旧目录中的exe；解压新的完整包，保留自己的路线和战斗配置备份。

## 本轮技能方案

用户描述的完整顺序为：邪恶攻击 → 切割 → 邪恶攻击 → 邪恶攻击 → 邪恶攻击 → 剔骨。怪物还活着时继续邪恶攻击；新目标再从开场开始。同一目标走近或重新进入攻击范围不会重放开场切割。

用户已确认 **2＝邪恶攻击、4＝切割、3＝剔骨**。完整开场是242223，目标没死时持续按2。当前源码的“剔骨键”预选“3（剔骨）”；应用方案不会修改游戏按键，也不会自动开始运行。

载入自己的战斗配置后，点“应用盗贼方案”，得到：

| 设置 | 值 |
| --- | --- |
| 开场一次 | 242223 |
| 之后循环 | 2 |
| 尝试间隔 | 750ms，可改500ms |

当前技能配置支持1至4。现场记录中的1是普攻开关，盲打会跳过它；2和4已经分别用于邪恶攻击和切割，盗贼方案不会把这些键重复冒充剔骨。以后改变游戏绑定时，应同步调整方案。

## 在界面里设置

1. 进入“目标与基础打怪”，先载入你实际使用的路线和战斗配置，不要把演示地图当真实路线。
2. 保持已确认的游戏动作条：2是邪恶攻击、4是切割、3是剔骨；1仍为普攻开关时不把它加入职业技能循环。
3. 应用盗贼方案。也可手工编辑“开场一次”和“之后循环”；开场留空表示沿用旧的整段循环。
4. 间隔先用750ms，需要比较时改500ms。这里是**发送按键尝试的间隔**，客户端是否接受技能还取决于实际能量、冷却、朝向和距离；工具不会把每次按键都记作施法成功。
5. 保存战斗配置。若继续使用原CLI启动方式，必须让启动命令读取这份新保存的配置；只更新exe不会把你原来的112自动改成盗贼开场。新CLI日志开头会显示开场、循环和间隔，可据此核对是否读对文件。
6. 修改配置会停止旧运行并清空人工确认。完成实际绑定与地图标定后再重新确认、启动；不要把未知坐标或盲打的尝试行为当作已测准的定位。

“应用盗贼方案”只改技能配置，不会自动开启Blind兼容模式。CLI现有grind入口沿用其显式盲打行为；载入的配置若本身是严格模式，界面不会暗中放宽射程和状态检查。

## 第一次实机怎么复测

先在可控单怪场景测试一只，再测试第二只。观察并记录：

- 普攻保持开启，动作条2有尝试；目标选中后不会连续走位数秒却完全不按技能。
- 第一只按开场顺序尝试，开场结束后只继续2；第二只从开场第一拍重新开始。
- 目标死亡后不再发下一拍；F12或失焦立即停止并释放本工具持有的键。
- 分别记录750ms和500ms下哪些技能实际成功，尤其切割、剔骨在能量/连击点不足时是否未施放。当前没有逐技能成功确认，固定按键开场不能保证每项实际成功，不能据按键次数推算伤害。
- 保留实际目标、玩家朝向、动作条绑定和停止原因。UI用“导出本次记录”；CLI保留对应的grind日志。请注明工具0.7.1、客户端版本及使用的配置。

开发侧用真实FarmSession和假键盘以40ms节奏复现并检查了调度，未操作游戏。面对多人环境、目标位置保密、客户端技能接受情况与实际击杀效果，仍以新的实机记录为准。

以上开发验证属于此前修复的历史记录。用户确认剔骨键后的本轮只更新源码预选项和需求文档，按用户要求不运行测试、不重新构建安装包。此前0.7.1包可手动选择3后应用同一242223方案。
