# 自动钓鱼使用与实测指南

Windows 工具 0.7.0，兼容插件 0.5.1。主窗口新增“自动钓鱼”；旧的战斗、路线和完整流程继续保留。新增需求见 [需求整理](requirements/fishing-requirements.md)，实施选择见 [实施计划](fishing-plan.md)，最终检查实数见 [验证记录](verification.md)。

本功能只发送键盘操作：默认 `1` 投竿、`F` 收杆及 NPC 互动，返程使用录制路线。不会移动或点击鼠标，不点击浮标、物品或拾取窗口。`F` 能否在目标客户端实际收杆必须先单独测试；没有确认这一点时不要勾选实机绑定确认。

## 先看离线演示

1. 解压完整的 `WoWProbe-Complete-0.7.0.zip`，保留 `assets/fishing`、示例和说明目录，不只复制执行文件。
2. 打开 `WoWProbe.exe`，在主窗口进入“自动钓鱼”。
3. 点击“恢复钓鱼演示”，再点“开始钓鱼离线模拟”。演示使用合成游戏状态和虚拟声音，不打开真实输入后端。
4. 查看投竿、单次收杆、确认收获、包满返 NPC、等待清包和逆序回点。可勾选“模拟无水花”“模拟未清包”“模拟错误 NPC”观察停止或超时分支。
5. 使用“导出钓鱼记录”生成本轮报告。模拟的输入计数为 0，不能作为游戏效果验收。

## 游戏电脑准备

- 按 [完整指南](complete-testing.md) 安装兼容插件，在主窗口选择真实游戏窗口并定位状态面板，确认 WP1/WC3/WO4 的同序号数据稳定更新。钓鱼还会核对主读取来源是否仍然新鲜；保留旧缓存不能绕过停止检查。
- 先手动短按投竿键，再在真实咬钩时手动按 `F`，确认它确实收杆并产生自己的拾取。打开游戏 Auto Loot。`F` 的客户端作用和声音素材一样，都属于待现场验证条件。
- 核对默认播放设备和游戏输出设备一致，打开游戏音效。监听捕获系统播放混音，不录麦克风，也不把原始系统音频写入文件。其他应用提示声、其他玩家水花及不同音效包可能影响识别，先单独试听核对。
- 通过已有路线工作区完成当前地图、移动速度和转向标定，再导入钓鱼工作区；选对 Q/E、A/D 或方向键。即使只站桩，也可能需要恢复保存朝向，因此标定确认不能省略。
- 首次配置先不启用“包满返 NPC”。完成鱼点、路线、NPC 和外部自动售卖插件的验证后再启用。钓鱼模块只负责按 `F` 互动和核验空位，具体清包由你已有插件完成。

## 保存钓点、路线和 NPC

人工操作可使用界面按钮；需要在游戏中用配置热键时，先勾选“启用全局快捷键”。它们不会作为游戏动作注入。

| 热键 | 操作 |
| --- | --- |
| F5 | 站在钓点、朝向水面，保存当前位置及朝向 |
| F6 | 从该钓点开始录制去 NPC 的路线 |
| F7 | 在转角、障碍物前后及必要中间位置保存路点 |
| F8 | 到达 NPC 后结束录制 |
| F9 / F10 | 导出 / 导入这条路线 |
| F11 | 保存当前已选中的友方非玩家 NPC |
| Ctrl+F12 | 启动或暂停，释放组合键后才开始准备和倒计时 |
| F12 | 急停，释放工具拥有的按键 |

路线必须从保存钓点开始，保持同一地图、区域和可逆策略。不要用稀疏点跨过未记录障碍物，也不要把演示地图当实际地图。

选择 NPC 后，填写或核对完整名称再保存；界面截断的名称不能直接当完整身份。选 NPC 可使用已核对的 Tab 或 F6 宏绑定。**F6 同时可能是“开始录制”的配置热键**：空闲配置时需要使用游戏的 F6 宏，可以暂时关闭全局快捷键并使用界面按钮。进入准备和运行阶段后配置热键会自动解除注册；脚本不修改你的游戏绑定。

导入地图标定、钓鱼方案或路线会清除相关实机确认，导入不会启动。保存“钓鱼方案”可将鱼点、朝向、路线、NPC 和设置一起保存为严格 JSON；不使用 YAML。

启用返 NPC 且已载入有效路线时，可以从该路线的已记录节点加入逆序剩余路段，先回钓点、还原朝向再投竿。这次初始归位不计为售卖成功；不在记录节点的当前位置会被拒绝，不能从任意位置直线接入。首次现场测试建议从钓点开始，分段验证路线可走性。

## 先试听，再开始实机

1. 点击“监听声音（只读）”，观察环回状态和水花、包满语音、顶部字形的候选分数；此按钮不投竿。
2. 先人工投一杆并按真实水花手动收杆，核对候选是否对应自己的实际咬钩。再核对顶部包满文字及角色提示音，聊天框里的同一句话不应触发顶部字形匹配。
3. 在“查看启动条件”中核对当前观察和共享输入故障。分数是参考相似度，不是准确率，也不能保证排除别人的水花。
4. 勾选真实绑定、Auto Loot、声音来源、当前地图标定的人工确认；开启返 NPC 时还要确认外部自动售卖实际恢复空位。
5. 点“实机钓鱼（5秒后）”或使用 Ctrl+F12。程序先等有效状态和声音，再进入 5 秒倒计时；切回游戏，移开安全角，保持窗口前台。启动其他输入工作区会停止当前模式。

严格模式下，设备失败、切换默认设备、错误时间戳、断续或连续约 5 秒静音会令监听失效；旧声音候选不会保留到下一次监听或下一杆。F12、失焦、过期来源、地图变化、战斗/死亡和输入错误也会停止。

若明确勾选“声音不可用时仅保留 30 秒重抛”，声音失效后只保留无鱼讯的超时循环，不会凭旧候选按 `F`。它不会自动开启，也不能冒充正常监听。包满识别仍需独立的有效证据，不能将一个孤立的红字分数当成双通道确认。

## 正常运行中应看到什么

- 每杆仅短按一次投竿键。窗口内的第一个有效新水花最多授权一次 `F`；多峰、重复或过期声音不连按。
- 30 秒边缘若前一次施法尚未明确结束，最多等待额外 300ms；仍未结束则停止，不补 `F` 或 Esc。实际客户端刷新和端到端延迟需要现场核对。
- 观察到拾取或库存变化后，确认收获数才增加，再等 1 秒重抛。按过 `F` 但没有反馈时，保留原 30 秒截止，不重复收杆。
- 包满的声音、顶部字形或已知零空位形成规定组合后，取消当前窗口，正向回 NPC。找不到正确 NPC、商人身份变化或清包超时应停止。
- `F` 互动成功、商店关闭或等待时间到了都不能代替实际空位恢复。确认库存改变和空位恢复后，才逆序回钓点并恢复保存朝向。
- 本模块不代替外部售卖插件配置；与旧完整工作区的逐格售卖功能是不同流程，钓鱼不会输出物品点击。

## 停止、断点和反馈

停止可用“停止钓鱼”、Ctrl+F12 或 F12。工具取消自己的输入并尝试匹配释放；游戏已经开始的施法、移动或界面需要人工核对。输入发送/释放失败会进入共享故障锁，检查实际按键状态并重启工具后再测试。

运行或倒计时期间按住 Ctrl、Alt 或 Shift 也会停止，防止投成 Ctrl+1 或用 Shift 改变 Auto Loot；工具只释放自己拥有的钓鱼键，不释放你正在按的修饰键。Ctrl+F12 启动时应先完整松开组合键。

实机会话的断点位于 `profiles/user/fishing/last-checkpoint.json`。先载入相同方案，点击“读取保存断点”，核对记录阶段、地图和路点，人工回到要求的记录位置，再勾选恢复确认。恢复还要通过正常启动检查和倒计时；断点不会恢复旧水花、旧收杆、剩余持键或旧投竿窗口。路线断点保留记录方向，不能用最近点猜测代替。

售卖等待断点还保存原 NPC 身份和库存基线。恢复时仍须核对同一商人；暂停期间已清包，也要有真实空位和库存变化证明。恢复不会再按一次 `F`；商店已关闭时也不额外按 Esc 打开菜单。

点击“导出钓鱼记录”，回传完整 `reports/fishing-时间戳` 目录，并在 Markdown 中补充客户端版本、地图、职业、窗口分辨率、UI 缩放、播放设备、键位、售卖插件及复现步骤。报告区分模拟和实机尝试，保存事件分数、时间与原因；`game_validation` 始终保留 `pending`，自动完成不替你填写通过。

## 素材结果和待实测边界

当前四个水花、一个包满语音的回放匹配来自建模所用同一素材，不是独立准确率测试。约 130–138ms 仅指水花参考算法窗口；真实音频设备、缓存发布、UI 采样和键盘传输尚未计入，端到端 200ms 目标仍待实测。顶部参考字形已做合成/回放边界核对，其他字体、分辨率和 UI 缩放仍须现场校准。

本轮最终自动检查数量、界面流程、包内容与 Git 同步由 [验证记录](verification.md) 登记。真实设备采集、`F` 收杆、自动拾取、清包插件、路线地形、音频误触发和至少两小时游戏连续运行都保留为现场待测。0.7.0 包保留旧版本及阶段包，不把原视频、DOCX、聊天目录或原始系统录音装进发布包。
