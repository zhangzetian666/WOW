# 盗贼技能与盲打调度修复计划

本轮基线为远程main `16225db`，已拉取。用户要求每怪先按2（邪恶攻击）、4（切割）、2、2、2、剔骨，目标仍活着时持续2；按键间隔支持500或750ms，先用750ms。剔骨的实际键位尚待用户确认，不能把五位24222当作完整六技能，也不猜游戏绑定。

## 已有证据与实现选择

- 最新提交正文记录11月16日21:35射程位一直false导致一次攻击都未发；原提交的Blind修复保留，严格模式仍校验射程。
- 默认112/1500ms在Blind下每三拍只发一次2，因为1被识别为普通攻击开关而跳过；CLI的/startattack只维持普攻，不是技能施放成功证据。
- 现有配置和界面最低1000ms；只支持整段重复，无法表达开场一次后持续2。新增可选 `SkillOpeningSequence` / JSON `skill_opening_sequence`，原 `SkillSequence` 保持作为循环段；旧文件无新字段时保持循环语义。每个新锁定目标重置开场，相同目标重新进入Combat不重放开场。
- Blind的走位分支先于技能，需以实际40ms会话及持键节奏复现是否挤占技能。若复现，则到期技能优先于补位，仍保留短脉冲、目标身份、停止和时间边界。
- 仅改技能调度与配置，不把按键成功当技能成功，不臆造连击点、能量、冷却或法术成功。实际技能受客户端判定；500/750ms指按键尝试间隔。

## 任务与验证

1. **配置和旧文件兼容**：BattleProfiles及其测试先RED再GREEN；允许500/750ms，拒绝499及越界；可空开场、只接受1至4、旧文件加载、保存/克隆、严格文件字段边界。
2. **实际战斗顺序**：Farming与FarmSession测试先复现后修复；验证六拍开场仅一次、存活持续2、新目标重置、死亡不再发技能、严格模式不放宽，以及40ms实际会话中走位不能饿死技能。Blind跳过普攻开关不再占用整拍；全为普攻开关时给出明确停止原因。
3. **界面、CLI与报告**：战斗设置可编辑开场和循环，间隔支持500/750；盗贼方案须明确选择剔骨键后才可应用，不自动修改游戏绑定。配置修改清空人工绑定确认，导出包含实际配置；CLI启动记录开场、循环、间隔，便于实机核对。

## 复核重点

- 旧112文件与新增开场字段不可在导入/导出或完整方案中丢失。
- 250ms移动持键与40msTick下，500/750ms技能到期仍可发出。
- 同一目标不重复切割，新目标从开场第一拍开始，目标死亡优先于下一拍。
- 急停、失焦、陌生目标、释放失败的既有保护保持有效。
- 保存的人工确认不能让新技能配置自动成为已验证绑定；未选择剔骨键不能静默应用错误方案。
