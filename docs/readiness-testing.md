# v0.6 方案交接、自检与反馈说明

版本 0.6.0。本轮完善两台电脑间的方案交接、启动准备检查和测试反馈整理，继续沿用已有路线、战斗、死亡恢复与售卖功能。实际游戏客户端及连续运行验收仍待测试；开发侧结果以 [验证记录](verification.md) 为准。

Windows 工具为 0.6.0；插件仍为兼容的 0.5.0，WP1/WC3/WO4 线上格式不变。新增客户端上下文从已有只读数据继承，组件版本号不能代替实际兼容性验证。

## 一键携带完整方案

在主窗口进入“完整运行与恢复”。先整理三类路线、战斗配置、完整流程设置，再使用“保存完整方案”写出 `.wowplan` 文件。它是包含严格清单的受限 ZIP 容器，可整体复制到游戏电脑，再使用“载入完整方案”恢复。

方案携带内容包括：

- 打怪、跑尸及商人路线；关闭某条中断流程时可不携带其路线。
- 战斗配置、保护物品清单、清包和超时规则、打怪方向及循环开关。
- 配置实际引用的有效 PNG 头像；载入后放入用户方案缓存，不覆盖原图或其他缓存。

运行断点不随方案搬运，起始索引统一从第一点开始。全部实机确认与标定确认会清空，载入不会启动输入；到游戏电脑后仍须核对地图、按键、按钮和窗口布局。不要把另一台电脑的中断状态直接当成当前状态。

清单记录每个文件的长度与 SHA256。导入检查固定路径、重复条目、大小及计划语义；损坏或不匹配的方案会被拒绝，当前已载入计划不会因此被替换。校验值用于完整性核对，不是文件来源认证。

容量限制为：压缩文件与总展开数据均不超过 16 MiB，最多 256 个条目；单 JSON 不超过 2 MiB、清单不超过 64 KiB；单头像不超过 1 MiB 且不大于 512×512。只接受固定配置及引用头像，绝对路径、遍历路径、反斜线和大小写冲突条目不被接受。

## 启动前查看缺项

点击“检查启动条件”查看当前准备情况。结果分为三类：

| 状态 | 含义 |
| --- | --- |
| 已满足 | 当前可核验的配置或状态已符合条件 |
| 未满足 | 需要先处理的阻断项，例如地图不符、确认未完成、数据过期或输入故障 |
| 运行时检查 | 事件发生后再核验，例如尚未显示的复活按钮、未选中的怪物或商店中的物品格 |

自检会检查计划角色与连接、可逆性、必要人工确认、同步数据、窗口尺寸、当前坐标和血蓝、输入故障，以及当前已出现的战斗、光标物品、阻挡弹窗和复活邀请。当前死亡或幽灵状态还会检查相应恢复依据；当前保存怪物会检查其射程及接近条件。启用头像辅助时会核对参考文件。

程序不会要求在角色活着时预先显示死亡弹窗，也不会要求尚未到商人处就打开所有物品格。自检只读、不创建键鼠后端、不触发运行；它不能替代运行中的每一步校验。摘要窗口中的“保存摘要”可保存 Markdown 供核对。

真实启动前会用当前方案和当前观察重新自检，不复用上一次“已满足”的结果。有阻断项时不布防、不保留倒计时。准备条件满足只表示当前可继续启动核对，**不表示游戏已验收通过**。真实运行依然需要明确确认与倒计时；F12、窗口失焦、状态过期和输入故障仍按 [完整指南](complete-testing.md) 停止。

## 读取已有测试反馈

在完整流程工作区使用“读取测试反馈”，选择包含 `campaign-report.json` 和 `runtime-evidence.json` 的本轮导出目录。程序只读报告及清单指定的同轮 JSONL，不修改原文件，不导入为运行配置，也不会因为读取反馈而启动。

摘要列出报告来源、工具与可用客户端版本、虚拟时间与墙钟时间、最后状态、停止原因、近期同轮事件，以及缺失或无法关联的资料。日志中的 `planned_command` 只表示计划过的指令，不能当成已实际执行或游戏成功。来源不一致、非法路径或明确冲突会被拒绝；可选日志缺失或截断会在允许范围内提示。

0.5 旧报告没有部分关联字段，读取时会明确说明旧格式的关联限制。不会用已经清空实机确认或重写头像路径的导出配置，强行重算并比对运行时计划指纹。0.6 报告增加结构版本、运行 ID、客户端上下文及方向/循环信息，便于同轮关联。

读取范围有上限：报告 8 MiB、清单 4 MiB、单日志 10 MiB，最多 64 个日志且合计不超过 64 MiB。不会扫描无关目录、加载任意图片或跟随重解析点。Markdown 摘要始终保留 `game_validation="pending"`；自动摘要不能替用户补写通过结论。

## 本轮数据完整性修正

- 导入路线、战斗配置或标定时，保留界面中已经有效编辑的保护物品、空位阈值和品质规则，避免静默恢复旧设置。
- 新运行建立自己的事件列表，导出的本轮报告不夹带上一次模拟或实机会话的历史事件。
- 断点的阶段、完成与中断标记必须一致；矛盾状态不能用于恢复。

## 两台电脑的使用顺序

1. 在开发电脑上查看离线演示、整理方案，并保存 `.wowplan`。
2. 将完整程序包和方案复制到游戏电脑；安装兼容插件并载入方案。
3. 从只读状态、单次输入和短路线开始实测，查看自检缺项并逐项处理。
4. 运行本轮测试后导出完整报告目录，另外记录客户端、职业、分辨率/UI 缩放和复现步骤。
5. 回传报告目录；使用“读取测试反馈”整理摘要，再据实际现象适配和回归。

基础实测步骤见 [完整指南](complete-testing.md)，客户端支持边界见 [能力矩阵](capability-matrix.md)。本轮不增加 OCR、无插件操控或通用寻路，也不以模拟、自检或报告完成状态代替游戏验收。

## 开发侧复核与版本包

`build.ps1` 增加完整方案、断点一致性、反馈解析和自检域测试；`verify.ps1` 保留旧流程、协议与启动失败回归，并接入交接界面测试。`-SkipDesktopSmoke` 会明确跳过桌面与完整界面流程，不应把未运行的项目写为通过。

`build.ps1 -Package` 生成 `dist/WoWProbe-Complete-0.6.0.zip` 及旁置 SHA256。旧 0.5.0 与 Phase1/Phase2/Phase3 包保留；运行依赖系统 .NET Framework 与标准压缩库，不新增 NuGet，也不需要在游戏电脑安装开发侧 Python/Lua 测试依赖。最终执行结果、包核对与同步记录见 [验证记录](verification.md)。
