# 第三阶段基础打怪与恢复实施计划

> 用户于2026年11月11日明确授权继续开发第三阶段，当前无法游戏实测。按现有设计执行，不等待未具备的环境，不标记实测通过。

**Goal:** 实现目标库、巡航与TAB扫描、接近、技能循环、拾取、可选剥皮和吃喝恢复，并提供无游戏可运行的完整模拟和受保护的实机入口。

**Architecture:** 保留WP1状态面板，增加匹配序号的WC3扩展面板。纯状态机接收能力明确的观测，输出有目标身份约束的短按命令。模拟器提供完整虚拟状态；真实会话通过独立监控执行，同其他输入模式互斥，复用共享失败锁。

**Tech Stack:** 延续C#5、.NET Framework、Windows Forms、Lua5.1，不增加游戏电脑运行依赖。

**Spec:** [执行流程](development-workflow.md)第三阶段；[产品设计](requirements/product-design.md)3.4～3.6、6.3.1～6.3.4、6.3.7。

## 假设与实现边界

- 第一、二阶段实机仍待验收；用户允许先开发。第三阶段开发不等于游戏可用结论。
- 不读取游戏内存，不调用保护动作API；插件只读，外部工具发送显式启用的键鼠。
- 自动接近需要可确认的目标位置、攻击范围和地图标定。客户端缺少其中必要信息时暂停；可在已处于射程内时验证攻击，不盲按W追逐未知位置。
- 目标只匹配保存的怪物；NPC、玩家、不可攻击或身份未知目标不得攻击。目标丢失或同名换目标不得继续沿旧身份施法/拾取。
- 拾取、剥皮与恢复均须动作后的状态/事件证据；未知和超时不伪报完成。非蓝条职业不套用法力阈值。
- 本阶段不实现死亡跑尸、包满售卖；这两类事件停止并留下恢复位置。
- 文档使用Markdown，按模块提交Git并同步已授权远程仓库。

## Review Focus

1. 两屏序号、CRC或能力不一致时不能执行任何战斗输入。
2. 选怪后实际目标改变、玩家目标、未知攻击性、目标位置无效时不能继续旧动作。
3. 读条/GCD、重复帧和瞬时自动拾取必须正确处理；不可用技能不盲按。
4. 剥皮和吃喝需要明确完成条件，缺数据或补给超时应暂停。
5. 真实输入和模拟、路线、单次测试全部互斥；错误锁跨会话保留，回调取消后不得发送。
