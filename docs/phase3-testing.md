# 第三阶段：战斗与恢复使用说明

版本 0.3.0；第三阶段开发侧实现与离线验证已完成。开发侧交付与真实游戏验收分别记录；当前没有游戏电脑实测结果，实际客户端兼容性、地图标定、按键效果和事件支持均待确认。自动检查、界面流程和测试包交付状态以 [验证记录](verification.md) 为准。

## 先运行离线演示

解压第三阶段测试包，运行 WoWProbe.exe，从主窗口打开“目标与基础打怪”。使用“恢复演示配置”，再点“开始离线战斗模拟”，观察恢复、巡逻、TAB 扫描、接近、技能循环、拾取、剥皮和回到路线的状态变化。模拟不需要游戏，也不创建真实按键后端；停止后可用“导出本次记录”保存报告。

包内示例是 `profiles/examples/simulation-battle.json` 和 `routes/examples/simulation-square.json`。两者使用合成地图 900001、模式 2、区域 `Simulation only`，目标为“演示野兽”。示例的键位、地图标定和目标坐标确认均为未确认，不能直接用于真实游戏。模拟成功只证明虚拟流程，不证明当前客户端具有相同接口或按键效果。

“载入路线”“载入战斗配置”“保存战斗配置”分别处理路线和战斗设置。“导入地图标定”使用第二阶段已测量的标定；本窗口不重新测量转速或地图比例。可调整技能顺序/间隔、血量/法力与恢复阈值、射程槽位、剥皮与接近选项，以及正反向、循环和起点/断点。修改后保存配置，切换配置前先停止当前运行。

## 安装插件并确认只读能力

1. 按 [第一阶段安装说明](../README.md) 安装同一测试包中的整个 `WoWProbe` 插件目录（源码位置为 `addon/WoWProbe`）。先确认客户端版本、主窗口数据和第一阶段单次短按，不跳过基础验收。
2. 保持游戏可见、窗口化，定位原 WP1 网格首色块中心。新增 WC3 战斗网格位于其右侧 272 个物理像素；两包应来自同一截图、更新序号相同。两块网格都不能被窗口遮住。
3. 手动选择活怪、NPC、玩家和尸体，核对目标身份、可攻击性、死亡状态、射程、动作条、施法和事件能力。读取不到的字段应显示未知。旧 WP1 仍可用于诊断；WC3 缺失、损坏、序号不同或过期时禁止真实战斗输入。
4. 在游戏中用 `/wowprobe range n` 选择射程检查使用的动作条槽位，`n` 为 1 至 4。配置中的范围槽位须一致；确认当前动作条页面的技能与工具 1 至 4 键实际对应，未读到冷却或可用性时不能当作可用。

## 保存目标与参考头像

用“保存当前怪物”“保存当前NPC”保存当前目标，也可“手动添加怪物”或“删除选中目标”。目标完整名称与名称哈希须一致；类型为 `monster` 的目标才参与选怪，NPC 条目仅供保存。工具还要求实时目标可攻击、非玩家、明确存活、身份有效。名称显示可能被截短，匹配依据完整名称哈希，不按同名前缀猜测。

参考头像仅用于人工核对。配置里的 `avatars/*.png` 相对于保存该配置的文件夹，例如个人配置保存在 `profiles/user/` 时，头像位于 `profiles/user/avatars/`。保存配置到其他文件夹时，相应参考图会随配置复制到该文件夹的 `avatars/` 子目录；找不到的参考图会清空引用。不进行头像图像识别，不用截图推断目标身份、方向、射程或可剥皮性。无法可靠取得参考图时保留为空，不影响已知身份的校验。

配置和路线可分别导入、保存。JSON 会检查版本、字段、数值边界与地图身份；非法文件不会替换原有有效文件。不要把离线示例的合成地图改名后当作真实路线，应从游戏有效状态录制并按第二阶段指南完成标定。默认个人配置与其参考头像位于 `profiles/user/` 下，它们不进入源码提交。

## 键位与真实启动

本阶段使用以下固定动作键；它们必须在游戏内由用户正确绑定。程序不会修改游戏绑定。

| 动作 | 按键 |
| --- | --- |
| 扫描目标 | TAB |
| 技能序列 | 1、2、3、4 |
| 与目标交互/拾取 | F |
| 剥皮 | 5 |
| 食物 | 8 |
| 水 | 9 |
| 紧急停止 | F12 |

移动使用路线阶段已验证的 W/S、Q/E、A/D 与空格组合。真实启动前确认配置与当前路线的地图、区域、朝向换算、转速和移动速度一致，确认固定动作键与移动键；真实地图标定确认和键位确认均为必需。技能顺序仅允许 1 至 4，例如 `112`，按配置间隔和可用性发送有限短按，不会按住技能持续重发。

启用自动接近还需要明确确认目标坐标来源，以及同地图的目标位置、有效射程和匹配的范围槽位。旧版 `GetPlayerMapPosition("target")` 不作为目标坐标证据；客户端缺少可靠目标位置接口时保持自动接近关闭，只验证已在可靠射程内的保存目标。启用接近而能力未知会停止；勾选确认也不能补出缺失能力。接近距离与重接路线距离均有限制，不生成未知长捷径。

点击“实机打怪（5秒后）”后切回游戏并保持前台；每次短按由独立监控释放，再等待新有效帧。攻击、拾取和剥皮发送前再次确认锁定目标身份与生死条件。更换同名目标、丢失目标或读取异常均不会沿用旧身份继续操作。

离线模拟、真实战斗、路线巡航与单次按键测试互斥。点击“停止”、失焦、F12、过期数据、死亡、灵魂、包满、危险低血或地图变化时停止并释放本会话持有的键，不自动恢复。若底层输入发送或释放出错，共享失败锁阻止通过换窗口或重建会话继续发送；先人工检查键状态和客户端，再重启工具处理。

## 拾取、剥皮与恢复证据

目标死亡需要不同帧确认，目标消失不算死亡。拾取通过新发生的 loot 打开/关闭事件判断，瞬时自动拾取也需事件证据；超时只允许有限重试。启用剥皮时需要已知可剥皮标记和专用成功事件，至少等待配置时长；无法确认不能报告剥皮成功。明确不可剥皮则跳过。

脱战后低于阈值才使用食物或水，并等待血量/法力达到恢复阈值。没有补给或没有恢复证据会超时停止；非 mana 职业忽略法力阈值。本阶段不实现死亡跑尸、复活、包满回城或售卖；遇到相应中断只停止并保留进度信息。

## 游戏电脑验收与反馈

先在短路线、单个已保存目标上验证：只读能力、每个动作键、目标身份变化停止、未知射程/坐标停止、施法等待、死亡确认、拾取事件、可选剥皮证据、低血低蓝恢复和无补给超时。最后测试 F12、失焦、遮挡色块和包满中断；不要用完整模拟结果代替这些实测。

每轮记录客户端版本、职业、地图、动作条页面、配置、复现步骤和实际结果，导出主窗口及战斗窗口报告。“导出本次记录”写入 `reports/farm-时间戳/farm-report.json`。参考头像文件不保证包含在报告目录中，反馈需要图片时请另外附上配置文件夹下对应的 `avatars/` 图片或色块截图。报告中的模拟与实机状态应分开，未测项目保留为未测，不自行改为通过。

## 开发侧复现

运行 `build.ps1` 编译并执行 C# 域测试；运行 `verify.ps1 -PythonPath <python.exe>` 执行完整验证，包括真实 Lua 5.1 测试、WP1/WC3 交叉解析、专用模拟色块桌面捕获、主窗口/路线/战斗预览和离线界面流程。`-SkipDesktopSmoke` 会明确跳过桌面与界面检查。游戏电脑不需要这些开发依赖。

本轮开发环境的真实桌面捕获遇到原生句柄错误；主窗口、路线窗口与战斗窗口预览均使用已标明的 `DrawToBitmap` 自有窗口绘制回退。它只验证窗口布局，不代表真实屏幕读取通过。统一验证明确跳过桌面捕获，离线界面流程单独执行并通过；脚本不会把 `screen_capture=false` 的回退当作真实截图检查成功。

`build.ps1 -Package` 输出 `dist/WoWProbe-Phase3.zip` 及其 SHA256 文件，保留既有 Phase1/Phase2 包。构建、检查与报告不会自动提供真实游戏验收结果。
