# 完整开发版使用与分步验收

版本 0.5.0。开发版覆盖巡逻战斗、死亡恢复、包满售卖和返回续跑；真实客户端、地图、按键与物品处理仍待游戏电脑验收。自动检查与模拟结果见 [验证记录](verification.md)，接口支持范围见 [能力矩阵](capability-matrix.md)。

## 先在没有游戏的电脑上查看流程

解压 `WoWProbe-Complete-0.5.0.zip`，运行 `WoWProbe.exe`，在主窗口点击“完整运行与恢复”，再点“恢复演示方案”和“开始完整离线模拟”。可查看回血回蓝、选怪、战斗、死亡、释放灵魂、沿记录路线跑尸、复活恢复、包满返商人、售卖和原路返回。离线模式不创建真实输入后端，报告中的系统输入为 0。

演示默认在首次击杀后注入死亡、第二次击杀后注入包满，两种中断各一次。还可测试缺少尸体数据、没有补给、错误商人、物品元数据未知、售卖前商店关闭等情况；这些场景应停止，保留失败原因。循环压力场景推进两小时**虚拟时间**，其中的实际执行耗时另行记录，不代表游戏已连续运行两小时。

示例文件均绑定合成地图 `900001 / 模式 2 / Simulation only`：

| 文件 | 用途 |
| --- | --- |
| `routes/examples/complete-farm.json` | 打怪区域闭合路线 |
| `routes/examples/complete-corpse.json` | 墓地到打怪区的记录路线 |
| `routes/examples/complete-vendor.json` | 打怪区到商人的记录路线 |
| `profiles/examples/complete-battle.json` | 演示怪物、商人和战斗设置 |
| `profiles/examples/complete-settings.json` | 完整流程、保留物品和超时设置 |

这些合成坐标用于模拟。真实游戏计划须使用自己录制的路线、目标及地图标定。

## 安装与基础验证

1. 把整个插件文件夹复制到游戏 `Interface\AddOns\WoWProbe`。同目录的 `WoWProbe.lua`、`Operations.lua` 和 `.toc` 必须来自同一测试包；运行程序前解压到可写目录。
2. 先按 [第一阶段说明](../README.md) 核对客户端版本、只读状态、单次按键、F12 和失焦释放；再按 [路线指南](phase2-testing.md) 验证短直线、转弯和地图标定。
3. 窗口化运行并露出左上角三个面板。定位原 WP1 面板第一个色块中心，程序须收到同一更新序号的 WP1、WC3、WO4；缺少完整扩展时可继续基础诊断，完整自动输入会拒绝启动。
4. 三个面板在默认色块 8 像素时横向共占 800 物理像素，参考头像位于其右侧。调整分辨率或 UI 缩放后，重新定位、核对窗口尺寸和标定；窗口及其他界面不能遮挡面板。

## 准备真实计划

先在路线工作区录制打怪路线，再录制墓地到打怪区的 `corpse_run` 和打怪区到商人的 `vendor_return`。记录拐角和障碍物前后的点，禁止依靠未知地形的直线捷径。三条路线须绑定同一地图、模式和区域，跑尸路线末端及商人路线起点连接到打怪路线首点。逆向打怪时以逆向后的路线首点为连接点。商人路线和打怪路线须允许逆序回放。

在战斗工作区保存怪物与商人 NPC 的完整名称、参考头像和真实地图标定。完整流程窗口使用“载入打怪路线”“载入战斗配置”“载入跑尸路线”“载入商人路线”“载入完整流程设置”分别导入，再用“导入地图标定”核对实测标定。文件尚未全部匹配时可继续导入，启动时才整体校验。任何文件替换或设置变化都会停止当前运行；完整计划与断点根据全部路线、配置及方向绑定，修改计划后旧断点不可直接套用。死亡恢复的回程也需要打怪路线允许逆序，即使未启用商人流程。

NPC 选取默认使用 **F6**：由用户在游戏里建立选取该 NPC 的宏，例如 `/targetexact NPC完整名称`，并确认 F6 绑定。其他固定键位为：F 交互、B 打开全部背包、Esc 关窗口、5 剥皮、8 食物、9 饮水、1–4 技能。移动与转向沿用已经验证的路线标定。客户端实际绑定须逐项核对。

启动实机前确认当前地图标定、全部按键、窗口布局及“允许处理完成后继续原打怪路线”。可用“读取当前窗口尺寸”回填尺寸，再人工核对界面布局。这些实机确认不随设置文件自动启用。“实机完整运行（5秒后）”有 5 秒倒计时，倒计时内切换到游戏。F12、停止按钮、鼠标移到屏幕左上角安全区、失焦和过期数据会停止自动输入并释放工具持有的键或鼠标按钮；已经开始的游戏动作可能需要人工取消。

监控读取只使用内存中的有效观察，截图和头像计算在界面生产端完成；超过 900 毫秒的旧抓图不会因延后处理而重新变成新数据。建立运行记录失败或输入后端准备失败时，不会保留一个仍在倒计时的会话。

## 死亡恢复验证

先选择可控、安全的测试位置，逐次检查：不同新帧确认死亡且血量为 0、可见可用的释放按钮、实际幽灵状态、实际尸体坐标、墓地路线、尸体恢复冷却为 0、可见可用的复活按钮、不同新帧确认存活、血蓝恢复、返回原打怪索引。

尸体位置必须来自当前客户端数据，死亡时的角色坐标不能替代未知尸体坐标。仅支持连接到已记录路线走廊内的尸体；不在范围内、地图变化、幽灵状态丢失、他人复活邀请、未知按钮或弹窗都会停止。应换几个死亡位置重复验证并据结果补路线，不能以一个地点成功代表整个区域可恢复。

## 包满与逐格售卖验证

总空位持续为 0 时，完整流程先在不同帧确认并等待 3 秒，再保存打怪断点、停止战斗输入、关闭旧拾取窗口并沿记录路线返商人。只出现提示但空位数据不一致时暂停等待；死亡优先于售卖，恢复后仍包满则接着处理售卖。

只有保存的、确认不可攻击的非玩家 NPC 可用于交互。商店自身的 NPC 身份还须与所选 NPC 一致。F 打开商店后使用 B 打开背包；售卖只在明确的出售页、空鼠标指针、没有确认弹窗、可验证的可见物品格位置下执行。

默认只卖已缓存、可售且品质为灰色的物品。食物/饮水等消耗品、任务物品、锁定物品、保留 ID、无售价和未知分类一律保留。可选白色物品规则须在设置中明确启用；当前不支持扩大到绿色及更高品质。先把自己需要保留的物品 ID 写入保留清单，再核对回放结果。

每次右键只针对一个明确格子。程序等待新的库存更新、原格变空及空位增加来确认成功；其他格的变化或重复旧帧不能当作售卖成功。商人关闭、切到回购页、物品移动、未知数据、弹窗或超时会停止，不自动确认销售提示、不删除物品。空位达到阈值且包满信号消失后，Esc 关闭商店，确认新关闭事件后沿商人路线逆向返回，并从原打怪索引继续。

“服务器对话后自动清包”默认关闭。只有实际验证服务器具备该功能后才启用；该模式不右键物品，仍要求库存发生变化且空位恢复的证据，超时则停止。

## 日志、截图与反馈

点击“导出本次记录”，在 `reports/campaign-时间戳/` 查看 `campaign-report.json`、`runtime-evidence.json`、本轮 JSONL 与五份配置副本；实机会话报告还包含断点。清单中的 PNG 截图会随运行证据复制，有效参考头像也会随战斗配置另存；抓取不可用或参考文件无效会保留相应原因或空引用。日志分别标注观察来源、计划指令、UTC 时间和虚拟时间；计划过的按键不等于游戏已经执行成功。所有未实测报告保持 `game_validation="pending"`。

运行证据按受控文件名保存，单个日志上限约 10 MiB，旧日志保留 7 天，截图保留 30 分钟，并有文件数上限。关键失败截图受当前屏幕抓取能力限制；抓图失败也须保留原因。界面自身绘制预览只验证布局，不算真实桌面截图通过。

“同时核对保存的头像”默认关闭；启用后，相似度须达到设置阈值，并有同目标、未过期的结果，未知或不符时停止。完整名称哈希和实时身份始终是必要条件，头像分数只能增加核对门槛，不能单独建立身份。它不提供 OCR 或无插件的图像操控回退，也不能代替未知尸体、按钮或物品证据。

回传时保留本轮报告、使用的五个配置文件、客户端版本、职业、分辨率/UI 缩放和复现步骤。真实游戏需分别完成单点动作、两条中断链路和约定地图上的至少两小时连续运行，才能登记相应实机验收；开发侧虚拟压力测试单独记录。

## 开发侧复核

`build.ps1` 编译并执行 C# 域测试；`verify.ps1 -PythonPath <Python 3.12 路径>` 还执行 Lua 5.1、真实 Lua 三包交叉解析、精确像素布局、隔离启动失败回归、桌面抓图和界面流程。`-SkipDesktopSmoke` 显式跳过桌面及完整界面流程，隔离启动失败回归仍执行，其他界面可另行运行测试程序。`build.ps1 -Package` 生成完整包及旁置 SHA256，不覆盖此前 Phase1/Phase2/Phase3 包。最终执行结果以 [验证记录](verification.md) 为准。
