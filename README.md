# 独立钓鱼客户端 · FISHING 1.0.14

这是从自动打怪主线拆出的钓鱼客户端。源码维护在 [FISHING 分支](https://github.com/zhangzetian666/WOW/tree/FISHING)，入口为 `WoWFishing.exe`，不会启动打怪窗口。坐标读取、移动和录制商人路线复用主线的基础代码；main/chief 的源码与客户端没有被替换。

## 使用步骤

1. 将包内 `addon/WoWProbe` 安装到实际游戏版本的 `Interface/AddOns/WoWProbe`。配套版本是 **0.5.18-fishing**；游戏已运行时输入 `/reload`，并让左上角色块面板保持可见。
2. 打开 `WoWFishing.exe`。把钓鱼技能放在数字快捷键上，在界面填写对应数字，默认 **1**。**F** 绑定“与目标互动”，**B** 打开背包，**R** 回复私信，开启游戏自动拾取。移动默认使用方向键↑、←、→。
3. 在“钓点与售卖路线”点击“保存坐标（追加钓点）”，每次新增一个当前位置和面水朝向，文本框立即显示编号及坐标，支持最多 500 点。旧 A/B/C 保留为前三点。所有点必须同图，相邻点及末点回首点的连线都应是可步行岸线；末点自动连接首点，无需重复保存起点。随机模式至少两点，固定模式至少一点。
4. 在“水花与聊天”框选自己的浮标出现的水面小区域。程序临时最小化窗口后取画面；选区保存为相对比例，不保存截图。尽量避开他人浮标、姓名板和岸边动画。换点后浮标仍应落在该区域内。
5. 按需录制 NPC 路线：在岸边接入点点“开始录制”，手动走到商人旁，选中商人，回到窗口点“结束并保存”。也可导入打怪客户端已有路线及移动标定。同一个 NPC 可售卖并修理；背包满后去路线起点，沿路线到 NPC，完成商店交互后原路返回，再恢复钓鱼。
6. 调整延迟、驻留时间及可选功能，点击“开始钓鱼”。运行中再次点击会先停止旧任务，待按键释放及旧线程退出后启动新一轮，无需先按停止。**停止或 F12** 释放脚本按键并取消自动重试。游戏失去前台时保留任务并暂停输入；回到前台、关闭聊天框并松开Alt/Ctrl/Shift后自动恢复，无需再点开始。
7. 在“恢复与重启”勾选异常自动重试，并填写秒数（默认 30，支持 1–3600）。新增“失焦后无人操作自动切回游戏”选项，默认勾选：键鼠连续空闲达到上述秒数、修饰键及鼠标键松开后尝试恢复游戏前台；正在操作其他窗口时不切走。游戏前台稳定0.5秒后继续，不额外叠加重试等待。取消该选项则需手动切回游戏。手动停止、F12 急停和输入发送故障不自动重启。
8. 在“死亡跑尸”从灵魂医者附近开始录制，沿可通行路线走到钓鱼区，再结束并保存；存活或灵魂状态均可录制，途中复活不妨碍结束。也可导入打怪客户端的 `quick-corpse-route.json`。保存后启用自动跑尸：死亡记点→释放灵魂→沿录制路线至终点→接近实际死亡点→点击已识别的尸体复活按钮→确认连续存活状态→返回钓点。不会与灵魂医者交互。路线与钓点需同图；缺失真实死亡/尸体坐标时不会猜测。

首次使用需要保存实际钓点、观察区域和本机移动标定。自动售卖沿用原客户端的商店交互以及游戏端/现有插件的售卖规则；不会擅自清空所有背包格子。没有卖出反馈时不会报告售卖成功。

## 1.0.14 失焦恢复与自动上下线

- 失焦立即释放脚本按键，记录当前前台窗口；按上述可选空闲恢复规则切回游戏，确认前台后才继续输入。不会关闭前台保护向其他应用发送钓鱼快捷键。旧杆结束帧缓冲从300毫秒扩展为2秒，期间不按F或ESC，减少短暂读取延迟导致的重启。
- 勾选“启用随机下线和重新上线”后，每轮按在线小时范围抽取时间；到时等当前杆结束，打开ESC菜单并核对登出按钮。点击后至少等待20秒，期间不再次按ESC、不移动、不重复点登出；加载画面和仍可见的登出倒计时继续等待。
- 确认已离开角色后，才按离线小时范围开始计时。到时核对角色选择界面，回车进入**当前选中角色**；加载期间不连续回车。不会按角色名重新选择其他角色。
- 识别登录后的插件/Lua错误或用户提供的“WoWProbe已被禁用，因为该功能只对暴雪的UI开放”提示，两次核对同一个“忽略”按钮后点击。**不会点击“禁用”**，也不会点击没有匹配提示内容的同名按钮。登录后确认3秒稳定世界画面、弹窗/光标状态正常及新的反馈帧，再重新计算在线时长并返回钓点钓鱼。运行中再次出现已识别的插件确认弹窗也使用同样规则处理。
- 上下线途中失焦或菜单OCR暂时不可用，保留当前阶段和离线截止时间，恢复后继续；停止/F12仍终止任务。账号密码、验证码等需人工处理。

验证：308项C#、88项Lua检查通过，包含上下线完整流程的虚拟时钟/模拟窗口回归；用户提供的真实弹窗图片经Windows OCR识别到了“忽略”文字矩形。未把图片识别和模拟流程标记为游戏内完整上下线通过，首次实际登出/重新上线仍需观察日志。

## 前进速度的单位

1.0.13 将前进标定范围从 **0.0001–0.2** 扩展到 **0.0001–1.0**，输入框步进为 0.0001；设置保存、路线导入、底层校验及速度估计上限保持一致。旧设置不自动改写。该值是采用横纵比例修正后的 **0–1 地图单位/秒**，用于计算按住前进键的时间。填写更大值会缩短按键时间，不能提高游戏里的实际跑速。

通常无加速效果时，角色跑步约为 **7 码/秒**（步行约 2.5 码/秒），可参照 [TrinityCore 的基础移动速度定义](https://main.trinitycore.net/d1/deb/unit_8cpp_source)。这与地图单位不是同一单位，不能将 7 直接填入标定框；不同地图的尺寸也不同。

以界面显示的 0–100 坐标计算，标定值 = `sqrt((ΔX × 地图横纵比例)² + ΔY²) ÷ 100 ÷ 实际前进秒数`。例如 X 不变、Y 从 40.00 到 42.00，用时 10 秒，则为 **0.0020**。应在平地直线跑、无转弯或停顿时测量；换地图或移动状态后重新测量。脚本当前仍保留接近钓点时的短按与到点提前松键保护，本次放宽输入不等于连续奔跑实机验收。

## 已加入的功能

| 功能 | 行为与默认值 |
| --- | --- |
| 抛竿延迟 | 每杆独立抽取，默认 0.3–1 秒 |
| 收杆延迟 | 鱼讯后独立抽取，默认 0–1 秒；快到本杆截止时缩短等待，过期不发送 F |
| 鱼讯来源 | 声音与图像可独立开关；图像跟踪红色浮标下沉及局部水花，静音可用；一杆最多收杆一次 |
| 随机钓点 | 按保存顺序连接所有点，末点连回首点；每段取内部随机位置，经公共端点移动，朝向按两端保存朝向插值 |
| 固定钓点 | 不勾选随机钓点时，从最近的已保存点开始，使用该点原坐标与朝向，驻留到停止 |
| 驻留时间 | 最短、最长两个分钟输入框；每个新钓点独立随机抽取，到点后计时，当前杆结束再换点；旧配置单值迁为相同上下限 |
| 背包查看 | 可选，默认随机间隔 10–15 分钟；直接按 B、等待“背包保持打开（秒）”后再按 B（默认 3 秒，可填小数），再次抽取间隔；不要求聊天/背包扩展反馈 |
| 定时按键 | 可选，在“定时按键”页填写数字键 0–9 及分钟范围，默认键 8、10–15 分钟；当前杆结束后按一次，等待至少 10 秒且读条结束，再重新计时 |
| 圈末聊天 | 可选，全部连线各轮换一次为一圈；从 1000 条简短话术随机选一句普通说话，连续两句不重复 |
| 私信回复 | 可选，只回复启动后新收到的私信；首次“这会有个电话，稍等回你”，同一发送者之后“稍等”；按 R 后核对回复对象 |
| 随机上下线 | 可选，在线与离线范围各默认 1–2 小时；当前杆结束后 ESC→登出，确认离线才计时，到期进入角色并重置在线计时 |
| 登录恢复 | 识别断线提示及登录/角色选择界面，使用已有登录条件确认并进入；遇到密码、验证码或登录失败等待用户处理，不保存凭据 |
| 自动售卖 | 包满触发已录路线；保留未完成商人行程进度；结束原路返回后续钓 |
| 异常自动重试 | 可选，在“恢复与重启”设置暂停后等待秒数，默认 30；等待旧线程结束再启动，不并发控制游戏 |
| 自动跑尸 | 独立录制/继续/取消/导入，死亡点自动保存；到录制终点后接近尸体复活，返回钓点续钓 |
| 彩色时间日志 | 抛竿前随机等待数值为红色，收杆随机反应时间为蓝色；文字日志文件仍为普通 UTF-8 |

背包、聊天、换点和计划下线均不会在等待鱼讯、延迟收杆或拾取确认期间插入。系统静音可能让声音识别没有信号，因此建议保留水花识别；真实水花阈值仍需在自己的水面验证。声音通过 [WASAPI 播放混音环回](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)读取，不录麦克风。

## 水面选区提示

1.0.12 新增死亡跑尸和多点追加保存，并为抛竿/收杆时间标红/标蓝。跑尸草稿与 NPC 草稿分开存放；到达跑尸终点的进度和实际死亡坐标会持久化，重启后可继续。无论看到复活按钮多早，都须先到已录终点；复活后等待脱战再接回钓点。该功能不包含自动打怪或食物补给。

1.0.11 在“钓鱼与时间”的背包间隔下增加“背包保持打开（秒）”，默认 3 秒，支持 0.1–3600 秒。倒计时从第一次 B 实际发送后开始；到期再按一次 B。等待期间不抛竿或移动；失焦时保留阶段，回到游戏后继续，不向其他窗口补按。旧配置缺少该字段时仍使用 3 秒。

1.0.10 将随机钓点驻留改为分钟范围，每次选择新点时抽取并写入日志；行走时间不计入驻留。同一点因失焦重新接近不重新抽取时长。背包间隔在“钓鱼与时间”显示“最短／最长”两个输入框，单位分钟，开关动作完成后重新抽取下一次间隔。自动重试倒计时显示在窗口状态及日志中，重复点击开始会合并为一次待启动请求。

1.0.9 修复合并 WO4 操作数据时把 WP1 拾取窗口已知/开关状态覆盖成默认未知的问题。空杆读条结束、确认拾取窗关闭并稳定后，按原先的随机抛竿延迟继续；不将空杆计为收获。“等待本杆鱼讯”是正常运行提示。临时等待日志现在区分游戏失去前台和 Alt/Ctrl/Shift 按住，任务仍保留，恢复条件满足后继续；日志更新不会主动弹出客户端。

1.0.8 在到点后立即根据保存的朝向校正面水方向，再开始抛竿倒计时；随机位置使用该线段两端朝向的圆周插值。请保存 A/B/C 时面向可钓水面。旧日志中的到点后退出同时伴有失焦记录，现沿用 1.0.7 的前台恢复流程继续校正，不因暂时切换窗口丢弃任务。

定时 B 和定时数字键不要求聊天/背包扩展反馈；坐标和钓鱼状态仍使用基础插件色块。1.0.13 修复自动聊天缺少 WF1 反馈就阻止开始的问题：只暂缓聊天/私信，继续钓鱼和定时动作，每隔至少 5 秒在空闲阶段重新检查。反馈恢复时跳过旧私信和旧圈次，只处理之后的新事件；发送过程中反馈丢失也取消本次聊天并继续钓鱼，仍核验频道和收件人。日志中的“反馈不可读”不能直接证明插件未安装，也可能是面板遮挡或采样未对齐；若需恢复聊天，检查配套插件及面板并 `/reload`。定时动作等当前杆结束再执行，售卖或行走中到期也会顺延；数字键按下后至少保留 10 秒，并等待实际读条结束，期间不插入抛竿、移动、背包、聊天或计划下线。失焦时保留已按键阶段，回到游戏后继续等待，不重复补按。

1.0.7 统一处理循环入口和按键过程中发生的失焦，不再因两次检查之间切换窗口而终止整轮任务。恢复前确认游戏前台和修饰键状态稳定500毫秒；等待旧读条结束后重新准备新杆，丢弃旧鱼讯，不补按过期F。不会向其他窗口发送游戏按键，也不会抢回前台；停止/F12、输入故障仍结束任务。

空竿确认结束后，直接使用“每次抛竿前随机等待”的范围，计时起点为本杆读条结束且拾取窗口关闭的首次有效观察，不叠加30秒期限或收获后固定等待。仍须确认读条和窗口状态稳定，避免打断尚未完成的钓鱼或拾取；收竿日志会显示正在等待的是读条还是拾取窗口。

1.0.6 补充短暂下沉后回弹、浮标下沉消失的检测；仅在实际钓鱼读条中接受图像鱼讯，避免结束时浮标消失误触发。建议先用默认阈值3.5；5.6较保守，降低阈值会更敏感也更容易误判，不能只靠调低数值解决所有漏检。日志同时显示最大下沉与下沉阈值。

收竿后确认读条已结束、拾取窗口已关闭且状态稳定500毫秒，即可准备下一杆，不再因缺少拾取计数一直等待原30秒期限。未确认收获仍不计为钓鱼成功；拾取窗口打开时不会抢先抛竿，延迟的拾取事件也会继续核对。该窗口状态使用现有插件色块，无需为本次客户端更新重新加载插件。

1.0.5 增加红色浮标稳定跟踪及连续下沉检测，小范围水花按局部区域判断，避免被大选区稀释。声音没有有效信号时，图像仍独立提供鱼讯。每5秒记录声音/图像状态、是否跟踪到浮标、水花值与阈值；识别成功记录“视觉鱼讯：浮标下沉”或“局部水花”，之后按用户配置延迟发送F。阈值越高越保守；浮标需在选区内，避开其他玩家浮标、UI及岸边动画。换了浮标外观或水面后需复测，不保证所有外观都能跟踪；跟踪不到时仍检测局部水花。

1.0.4 修复接近钓点时读取画面耗时额外延长移动按键的问题。接近目标缩短步长，按实际位移估算速度，进入到点范围提前松键；转向按键到时先释放，再读取下一幅画面。日志分别显示固定点字母或随机连线、当前坐标、目标坐标和到达提示。随机模式下目标本来就在 A/B/C 的连线上，不要求等于三个端点；关闭随机则使用最近保存点。

1.0.3 修复“查看已保存区域”中重新框选却未写入设置的问题；两个入口现在都能保存。只有图片不代表已经保存了选区，必须在画面中按住鼠标左键拖出绿色矩形，再点击“保存选区”。未框选时保存按钮禁用；配置页明确显示“尚未保存”或“已保存”。查看/修改时保留原选框，取消不会更改原选区。

## 录制中断与结束

1.0.2 新增“取消本次录制”按钮，位于“钓点与售卖路线”页。录制时可点击，立即停止采样并丢弃本次未完成点及当前自动草稿；不读取游戏终点，也不修改已保存的钓点、NPC路线或上一份草稿。取消后可重新开始录制。没有正在进行的录制时按钮禁用。


1.0.1 修复了短暂读取中断后持续报“位置跳跃”、无法结束的问题。开始录制时保持游戏在前台；每个新增路线点自动保存草稿。正常短暂漏读在位移合理时可恢复，真正长时间缺段或跨图不会拼成完整路线。

“结束并保存路线”遇到终点读不到、长缺段或只有一个点时，也会结束本次录制并保存草稿，不替换原有的可用售卖路线。界面和提示会列出最后有效坐标；回到该位置后点击“继续上次录制”补录，之后正常结束。已录草稿在关闭窗口和重新打开后仍保留。新开一次录制会把上一份草稿保留为 `fishing-npc-recording.previous.json`。

## 配置与日志

- `fishing-settings.json`：独立钓点、范围、路线与开关；支持导入、导出，导入立即更新界面。
- `fishing-npc-recording.json`：自动保存的录制点、地图和最后有效坐标，用于继续补录。
- `fishing-corpse-recording.json`：独立跑尸录制草稿，不覆盖 NPC 路线。
- `fishing-death-checkpoint.json`：本轮死亡坐标、路线匹配信息及跑尸终点进度，确认复活后清除。
- `fishing-vendor-checkpoint.json`：正在进行的商人往返进度，完成后移除。
- `fishing-runtime.log`：文字日志，每份约 2 MB，最多保留当前文件及 4 份轮换文件。
- `assets/fishing/chat-phrases.txt`：1000 条内置话术。

截图和原始录音只在内存处理，不落盘。圈数、抛竿次数、收杆与收获分开记录；仅有拾取/库存反馈才算确认收获。已启用跑尸且有同图路线时，死亡转入恢复流程；其他战斗、地图变化或不可核对的状态仍显示原因并按重试设置处理。

## 源码构建与测试

Windows + .NET Framework 4 编译器；测试还需要 Python 3 和 `lupa`（包含 Lua 5.1，本机验证为 lupa 2.8）。Python 可通过 `-Python` 指定。Lua 包也可安装在被 Git 忽略的 `.tools` 目录。

```powershell
python -m pip install --target .tools lupa==2.8
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-fishing.ps1 -TestOnly -Python python
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-fishing.ps1 -Package -Python python
```

安装包位于 `dist/WoWFishing-latest.zip`，目录产物为 `dist/WoWFishing`。兼容入口 `build.ps1` 在本分支只构建独立钓鱼客户端。

开发侧测试覆盖随机边界、单杆收杆、录制、三段移动、辅助动作互斥、静音视觉输入、Lua/C# 协议及配置保存等。虚拟长时测试和合成水花测试不能视为实机钓鱼通过。真实鱼讯准确率、F 收杆、售卖返回及断线重进仍需游戏验收，详见 [进度记录](docs/progress.md) 和 [需求记录](docs/requirements/standalone-fishing.md)。
