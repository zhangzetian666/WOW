## 代码与构建

- `src/`：Windows 界面、状态解析、路线与目标库、导航、战斗/恢复/售卖状态机、完整模拟、运行证据、方案封装、自检、反馈摘要及键鼠保护。
- `addon/WoWProbe/`：游戏内只读辅助插件。
- `tests/`：核心逻辑、Lua、跨语言协议及界面验证。
- `routes/examples/`：仅用于离线验证的示例路线。
- `profiles/examples/`：仅用于离线验证的战斗配置；真实地图、键位与目标须单独确认。
- `build.ps1`：编译并运行 C# 检查；添加 `-Package` 生成测试包。
- `verify.ps1 -PythonPath <python.exe>`：运行完整开发侧验证，需要 Python 3.12 及本地 `lupa.lua51` 测试依赖。

构建依赖 Windows 自带 .NET Framework 编译器和标准压缩库，不引入 NuGet。开发侧完整检查中的 Python 与 Lua 依赖不需要安装到游戏电脑。`bin/`、`dist/`、测试输出及本地依赖均不提交到源代码仓库。

开发者可用 Python 3.12 执行 `python -m pip install --target .tools lupa==2.8` 准备 Lua 5.1 测试依赖，再把该 Python 的完整路径传给 verify.ps1。

## 一次保存、换电脑载入

在“完整运行与恢复”工作区整理三类路线、战斗配置和保留规则，使用“保存完整方案”生成一个 `.wowplan` 文件。它保留打怪方向、循环及有效头像，可在另一台电脑用“载入完整方案”恢复；运行断点不随包搬运，所有实机确认清空，载入不会启动键鼠输入。

“检查启动条件”会区分当前已满足、未满足与运行时再查的条件；真实启动前还会重新自检。“读取测试反馈”只读已有报告目录并整理来源、最后状态和停止原因，可保存 Markdown 摘要。准备条件满足、模拟完成或报告显示已完成，都不等于实机验收通过。详见 [交接与反馈说明](docs/readiness-testing.md)。

Windows 工具为 0.6.0，插件仍使用兼容的 0.5.0 WP1/WC3/WO4 只读协议；组件版本不同不是游戏兼容性证明。旧 0.5.0 及 Phase1/Phase2/Phase3 测试包保留。

## 完整开发版快速开始

解压 `dist/WoWProbe-Complete-0.6.0.zip`，运行 `WoWProbe.exe` 并进入完整流程工作区，先使用默认演示计划运行离线模拟。演示包含死亡恢复和包满返商人，再回原路线；支持失败注入和两小时虚拟时间压力场景。虚拟时长与实际耗时分别记录，模拟不代表游戏连续运行两小时。

示例由 `complete-farm.json`、`complete-corpse.json`、`complete-vendor.json` 三条路线，以及 `complete-battle.json`、`complete-settings.json` 两份配置组成，均在对应 examples 目录。真实计划须用自己录制的路线、完整目标名称、地图标定及确认过的键位和布局。默认只售卖有明确证据的灰色物品，并保留消耗品、任务物品、保留 ID 与未知物品。

完整步骤及逐项反馈见 [完整指南](docs/complete-testing.md)。客户端暂时缺失尸体、物品分类、按钮矩形或目标坐标时，相关自动动作会停止；可选头像核对可额外要求同目标头像达到阈值，完整名称和实时身份始终是必要条件，没有 OCR 或无插件操控回退。现有 Phase1/Phase2/Phase3 包作为历史版本保留。以下分阶段说明继续用于从基础项目开始实机验收。

## 第三阶段快速开始

运行 WoWProbe.exe 并打开“目标与基础打怪”，使用“开始离线战斗模拟”查看演示。示例配置位于 `profiles/examples/simulation-battle.json`，与 `routes/examples/simulation-square.json` 的合成地图绑定一致。模拟展示食物/饮水恢复、扫描、接近、技能循环、拾取与可选剥皮；运行时不创建真实输入后端。界面和报告中的模拟结果只代表虚拟流程。

目标按保存的完整名称哈希和实时身份匹配，只选择可攻击的非玩家怪物。头像可保存为人工核对的参考图，不参与图像识别，也不能代替身份或射程证据。旧客户端若无法提供同地图目标坐标，自动接近保持关闭；启用接近但能力未知时停止，不猜方向移动。完整说明见 [第三阶段指南](docs/phase3-testing.md)。

第三阶段历史包为 `dist/WoWProbe-Phase3.zip`。当前 `build.ps1 -Package` 生成 `dist/WoWProbe-Complete-0.6.0.zip` 及 SHA256 文件，包含兼容插件、三类路线、配置示例及 Markdown 指南。游戏电脑不需要开发用 Python 或 Lua 测试依赖。

## 第二阶段快速开始

运行测试包里的 WoWProbe.exe，点击“路线录制与巡航”，直接使用“离线方形演示”开始模拟。模拟不会发送系统按键；正反向、闭合循环、受阻恢复和报告导出都可在没有游戏的电脑上验证。

真实游戏路线需从主窗口有效状态流录制，并核对地图和标定后才能启用。完整步骤见 [第二阶段使用说明](docs/phase2-testing.md)。路线功能继续包含在第三阶段测试包中，已有 `dist/WoWProbe-Phase2.zip` 保留为第二阶段历史版本。

## 第一阶段测试包使用说明

主窗口用于确认游戏客户端状态、屏幕读取、单次按键和急停是否有效。路线功能使用路线窗口，打怪流程使用“目标与基础打怪”。请先验证基础读取和单次短按，再按各阶段指南验收；实现入口不代表已在真实游戏通过。

适用环境：游戏电脑为 Windows 11。插件以文档中的 3.3.5 为候选基线，会检测实际版本与接口；是否兼容你的客户端须以这次测试为准。检测工具使用 Windows 自带的 .NET Framework，不需要安装 Python、Node.js 或编程工具。

## 1 把测试包放到游戏电脑

1. 将对应阶段测试包复制到游戏电脑并解压到普通可写文件夹。请不要直接在压缩包里启动程序。
2. 退出游戏，将解压后整个 WoWProbe 文件夹复制到游戏目录的 Interface\AddOns 中。
3. 确认目录是 Interface\AddOns\WoWProbe\WoWProbe.toc，避免多套一层文件夹。插件同目录的 Lua 文件都须一起复制。
4. 启动游戏，在角色选择界面的插件列表启用 WoWProbe。若提示过期，先确认客户端版本；3.3.5 对应接口号 30300。只有确认是本测试包时才选择加载过期插件，其他版本的兼容性仍待检测。
5. 进入游戏后应看到左上角彩色色块和状态文字。输入 /wowprobe info 查看版本、接口和键位诊断；/wowprobe show 显示面板；/wowprobe hide 隐藏；/wowprobe reset 恢复面板。

如果插件报 Lua 错误或完全看不到面板，先截图错误并发回，同时提供客户端版本。此时无需继续按键测试。

## 2 先建立只读状态连接

1. 游戏使用窗口化或无边框窗口，先按 1920×1080、界面缩放 100% 测试。保持游戏与工具以同一权限级别运行。不要先提高任何程序的权限。
2. 双击 WoWProbe.exe。默认只读取屏幕，不发送按键。
3. 点击“刷新窗口”，选择实际游戏进程和窗口；列表可能包含其他应用，务必核对进程名与窗口标题。
4. 色块宽度先保持 8。点击“定位首个色块中心（3秒）”，在 3 秒内把鼠标放到插件左上角网格的第一个小方块中心，不必点击。
5. 工具会自动记录位置并持续读取。不要用其他窗口盖住彩色色块。校验失败时会显示原因，不会把错误数据当作正常状态。
6. 等待界面显示“数据正在更新”。这表示收到连续变化的数据包；它还不代表移动、交互等功能已通过验收。

常见处理：选择错窗口、色块被遮挡、游戏最小化、选到格子边缘或尺寸不符时，重新选择窗口并定位。若画面经过 HDR、滤镜或串流颜色处理而解码失败，先发回色块截图和显示设置，避免反复猜测。

## 3 手动操作游戏并观察字段

请先不启用按键测试，用你自己的键鼠完成下面的变化，在工具下方逐项选择“通过”“失败”“未测”或“不适用”。

- 确认界面显示的客户端版本、build 和接口号；记录角色职业和地图。
- 手动前进与转向，观察坐标、朝向和序号是否更新。
- 选中不同怪物和 NPC，观察名称、目标血量和目标状态。
- 让血量与资源发生变化。非蓝条职业的资源类型可能是怒气或能量，工具会保留资源类型，不会假称法力值。
- 打开与关闭商人窗口、拾取窗口，观察相应状态。
- 检查背包空格；在可控条件下制造包满后的拾取失败，观察包满提示。仅空格数为零和真正出现包满提示是不同信息。
- 在你方便且可控的场景测试死亡、释放灵魂后的状态与尸体坐标。不方便测试可填“未测”，不要据此确认通过。

部分旧客户端在世界地图打开时无法稳定取得当前区域坐标。插件会尽量避免修改你打开的地图，无法确定坐标时报告不可读。关闭世界地图后再观察恢复情况。

## 4 按键只测试一次

1. 先核对游戏内绑定。A/D 与 Q/E 的转向和平移可能互换；F 也可能是协助目标。工具按你选择的物理键发送，不会代你修改绑定。
2. 在不会发生误操作的位置测试，确认游戏里没有打开聊天输入框、菜单或其他弹窗。
3. 选择一个按键，勾选确认，再点击“5秒后发送一次”。切回游戏，让游戏窗口处于最前台；鼠标移出屏幕左上角。
4. 5 秒后工具仅按住一次所选键约 120 毫秒，随后释放。用实际画面判断该键是否生效，再记录结果。
5. 任意时刻按 F12，或将鼠标移入主屏左上角 60×60 像素区域，可取消待执行或正在执行的按键。焦点变化、数据损坏或停止更新也会取消；不会自动继续。
6. 每次测试都需重新勾选确认。再次发送前先观察上一轮效果。

对拾取、NPC 交互和剥皮，要分别检查实际效果。F 未绑定交互、第二次 F 不触发剥皮或普通商人不会自动清包，都应记录真实现象。第一阶段不执行批量售卖。

急停验证：在倒计时中按 F12，应取消本次按键；也可在倒计时结束前切到其他窗口，应取消而非向其他窗口发送。真实按住期间的释放保护另有开发侧自动测试；120 毫秒的短按仍需在游戏电脑观察实际效果。

## 5 导出一轮结果并发回

1. 填写实机验收结果与备注，注明客户端版本、职业、地图、窗口大小、界面缩放、显示缩放和失败步骤。
2. 点击“导出本轮测试报告”。导出会先取消按键。
3. 工具旁 reports 文件夹里会生成本轮目录，包含 report.json、结果摘要.txt，以及成功读取过的色块截图。截图仅限色块区域。
4. 将该轮整个目录打包发回。无法连接时仍可导出报告，附上游戏中的报错截图或短录像。
5. 如需插件的完整诊断，运行 /wowprobe info 后执行 /reload 或正常退出游戏；再提供该账号对应 WTF\Account\...\SavedVariables\WoWProbe.lua 中的诊断文件。无需提供账号密码或整个 WTF 目录。

有两种记录需要分开：开发侧本地测试通过，以及你的实际游戏场景通过。未测试项目会保留为“未测”。只有实机关键项目通过后，第一阶段才完成验收并进入路线系统。

## 当前交付和下一步

当前完整开发包提供三面板只读插件、诊断与路线工具、战斗/恢复/售卖闭环、完整离线模拟、受控键鼠执行及运行证据导出。开发侧验证范围见 [验证记录](docs/verification.md)。真实客户端版本、屏幕抓取与全部动作仍需从基础项目开始验收，反馈后再做适配和优化。

开发源代码位于本仓库根目录。需要重新编译时在仓库目录运行 build.ps1；打包使用 build.ps1 -Package。普通游戏电脑直接运行已打包的 WoWProbe.exe。

接口依据：Microsoft SendInput 文档 https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput 。输入受前台窗口和进程权限条件影响，工具会检查返回结果；最终效果仍须在实际客户端观察。
