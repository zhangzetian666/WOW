# 独立钓鱼客户端 · FISHING 1.0.3

这是从自动打怪主线拆出的钓鱼客户端。源码维护在 [FISHING 分支](https://github.com/zhangzetian666/WOW/tree/FISHING)，入口为 `WoWFishing.exe`，不会启动打怪窗口。坐标读取、移动和录制商人路线复用主线的基础代码；main/chief 的源码与客户端没有被替换。

## 使用步骤

1. 将包内 `addon/WoWProbe` 安装到实际游戏版本的 `Interface/AddOns/WoWProbe`。配套版本是 **0.5.18-fishing**；游戏已运行时输入 `/reload`，并让左上角色块面板保持可见。
2. 打开 `WoWFishing.exe`。把钓鱼技能放在数字快捷键上，在界面填写对应数字，默认 **1**。**F** 绑定“与目标互动”，**B** 打开背包，**R** 回复私信，开启游戏自动拾取。移动默认使用方向键↑、←、→。
3. 在“钓点与售卖路线”依次保存 A、B、C 的当前位置和面水朝向。三个点必须同图，AB、BC、CA 都应是可步行的岸线。沿弯曲岸边、山石或水中跨越的连线不能靠坐标证明可通行，需重新选择点。
4. 在“水花与聊天”框选自己的浮标出现的水面小区域。程序临时最小化窗口后取画面；选区保存为相对比例，不保存截图。尽量避开他人浮标、姓名板和岸边动画。换点后浮标仍应落在该区域内。
5. 按需录制 NPC 路线：在岸边接入点点“开始录制”，手动走到商人旁，选中商人，回到窗口点“结束并保存”。也可导入打怪客户端已有路线及移动标定。同一个 NPC 可售卖并修理；背包满后去路线起点，沿路线到 NPC，完成商店交互后原路返回，再恢复钓鱼。
6. 调整延迟、驻留时间及可选功能，点击“开始钓鱼”。**停止或 F12** 释放脚本按键。游戏失去前台时暂停输入，回到前台后重新开始本杆。

首次使用需要保存实际钓点、观察区域和本机移动标定。自动售卖沿用原客户端的商店交互以及游戏端/现有插件的售卖规则；不会擅自清空所有背包格子。没有卖出反馈时不会报告售卖成功。

## 已加入的功能

| 功能 | 行为与默认值 |
| --- | --- |
| 抛竿延迟 | 每杆独立抽取，默认 0.3–1 秒 |
| 收杆延迟 | 鱼讯后独立抽取，默认 0–1 秒；快到本杆截止时缩短等待，过期不发送 F |
| 鱼讯来源 | 声音与水花图像可独立开关；视觉不依赖系统声音；一杆最多收杆一次 |
| 随机钓点 | AB、BC、CA 顺序轮换，每段在连线上随机取点；经过公共端点移动，朝向按两端保存朝向插值 |
| 驻留时间 | 用户可设置，默认每点 10 分钟；当前杆结束再换点 |
| 背包查看 | 可选，默认随机间隔 10–15 分钟；B 打开、3 秒后 B 关闭，再次抽取间隔 |
| 圈末聊天 | 可选，三段各轮换一次为一圈；从 1000 条简短话术随机选一句普通说话，连续两句不重复 |
| 私信回复 | 可选，只回复启动后新收到的私信；首次“这会有个电话，稍等回你”，同一发送者之后“稍等”；按 R 后核对回复对象 |
| 随机上下线 | 可选，在线与离线范围各默认 1–2 小时；当前杆结束后 ESC→登出，确认离线才计时，到期进入角色并重置在线计时 |
| 登录恢复 | 识别断线提示及登录/角色选择界面，使用已有登录条件确认并进入；遇到密码、验证码或登录失败等待用户处理，不保存凭据 |
| 自动售卖 | 包满触发已录路线；保留未完成商人行程进度；结束原路返回后续钓 |

背包、聊天、换点和计划下线均不会在等待鱼讯、延迟收杆或拾取确认期间插入。系统静音可能让声音识别没有信号，因此建议保留水花识别；真实水花阈值仍需在自己的水面验证。声音通过 [WASAPI 播放混音环回](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)读取，不录麦克风。

## 水面选区提示

1.0.3 修复“查看已保存区域”中重新框选却未写入设置的问题；两个入口现在都能保存。只有图片不代表已经保存了选区，必须在画面中按住鼠标左键拖出绿色矩形，再点击“保存选区”。未框选时保存按钮禁用；配置页明确显示“尚未保存”或“已保存”。查看/修改时保留原选框，取消不会更改原选区。

## 录制中断与结束

1.0.2 新增“取消本次录制”按钮，位于“钓点与售卖路线”页。录制时可点击，立即停止采样并丢弃本次未完成点及当前自动草稿；不读取游戏终点，也不修改已保存的钓点、NPC路线或上一份草稿。取消后可重新开始录制。没有正在进行的录制时按钮禁用。


1.0.1 修复了短暂读取中断后持续报“位置跳跃”、无法结束的问题。开始录制时保持游戏在前台；每个新增路线点自动保存草稿。正常短暂漏读在位移合理时可恢复，真正长时间缺段或跨图不会拼成完整路线。

“结束并保存路线”遇到终点读不到、长缺段或只有一个点时，也会结束本次录制并保存草稿，不替换原有的可用售卖路线。界面和提示会列出最后有效坐标；回到该位置后点击“继续上次录制”补录，之后正常结束。已录草稿在关闭窗口和重新打开后仍保留。新开一次录制会把上一份草稿保留为 `fishing-npc-recording.previous.json`。

## 配置与日志

- `fishing-settings.json`：独立钓点、范围、路线与开关；支持导入、导出，导入立即更新界面。
- `fishing-npc-recording.json`：自动保存的录制点、地图和最后有效坐标，用于继续补录。
- `fishing-vendor-checkpoint.json`：正在进行的商人往返进度，完成后移除。
- `fishing-runtime.log`：文字日志，每份约 2 MB，最多保留当前文件及 4 份轮换文件。
- `assets/fishing/chat-phrases.txt`：1000 条内置话术。

截图和原始录音只在内存处理，不落盘。圈数、抛竿次数、收杆与收获分开记录；仅有拾取/库存反馈才算确认收获。战斗、死亡、地图变化或不可核对的状态会暂停并显示原因，当前独立钓鱼版不启动打怪或跑尸。

## 源码构建与测试

Windows + .NET Framework 4 编译器；测试还需要 Python 3 和 `lupa`（包含 Lua 5.1，本机验证为 lupa 2.8）。Python 可通过 `-Python` 指定。Lua 包也可安装在被 Git 忽略的 `.tools` 目录。

```powershell
python -m pip install --target .tools lupa==2.8
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-fishing.ps1 -TestOnly -Python python
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-fishing.ps1 -Package -Python python
```

安装包位于 `dist/WoWFishing-latest.zip`，目录产物为 `dist/WoWFishing`。兼容入口 `build.ps1` 在本分支只构建独立钓鱼客户端。

开发侧测试覆盖随机边界、单杆收杆、录制、三段移动、辅助动作互斥、静音视觉输入、Lua/C# 协议及配置保存等。虚拟长时测试和合成水花测试不能视为实机钓鱼通过。真实鱼讯准确率、F 收杆、售卖返回及断线重进仍需游戏验收，详见 [进度记录](docs/progress.md) 和 [需求记录](docs/requirements/standalone-fishing.md)。
