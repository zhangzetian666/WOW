# WOW 自动打怪客户端

**当前版本：0.8.86，配套插件 0.5.17。** 项目提供一个 Windows 客户端 `WoWProbe.exe`，集中配置巡航、技能、拾取剥皮、恢复、跑尸和 NPC 售卖修理路线。旧 0–0.7 阶段的独立界面及历史客户端包已清理，源代码历史保留在 Git 中。

2026-11-24本机近战测试：0.8.69同一次约8分钟运行确认6次击杀、5次拾取，并完成包满前往NPC、装备耐久恢复100%、返回后再击杀2只的流程；观察期间没有死亡或脚本停止。最新实测结果、配置和验收边界见[开发进度](docs/progress.md)。这不代表远程射击、跑尸或全天运行均已实测通过。

游戏内辅助插件读取游戏 API，并通过屏幕色块输出状态；Windows 客户端解析这些状态及画面信息，通过键盘、鼠标执行动作。定时下线与上线额外使用 Windows OCR 识别菜单文字。

> 已有保存方案时，打开客户端会尝试自动启动。修改配置前可先点击“停止”或按 `F12`；显式停止会取消自动恢复。

0.8.86 修复复活宠物时的额外移动输入：E/Q发送前先只读确认坐标连续稳定1秒，只有观测到仍在移动才先停止移动；按8前不再补发前进键。Q后至少保持11秒输入锁，随后还须在至少3个不同状态帧中连续确认读条结束1秒，避免短暂的无读条反馈让脚本提前按8或走路。丢帧/自动重试会重新确认读条稳定结束，保留原Q计时。循环中已经确认宠物死亡后，即使尸体消失仍继续按Q复活，直到确认宝宝存活，不改成反复按E。

0.8.84 将角色死亡复活后的动作改成固定流程。启用“宠物恢复”后，本窗口观察到角色死亡/幽魂，跑尸复活完成后执行：

1. 先吃喝恢复，血量达到100%就结束恢复，不要求蓝量回满，也不额外等待原进食最短时间。
2. 固定按 `E` 召唤宠物，短暂等待1.5秒公共冷却，再固定按 `Q` 复活宠物。
3. 从Q实际发出时起原地等待至少11秒；若仍在读条，等读条结束后再固定按 `8` 施放雄鹰守护。
4. 继续循环打怪，不因蓝量未满立即重新坐下；首场战斗后恢复平常的吃喝规则。

上述E、Q、8不依赖宠物死活或是否出现，不因宠物状态未知、施法失败而跳过顺序；这一固定流程不使用聊天命令。已发出的步骤和等待计时在当前客户端窗口内自动重试时保留，再次角色死亡则从吃喝重新开始。按键发送完成不代表技能已成功生效，实际效果需游戏验证。

0.8.85：循环中确认宝宝死亡后，先完成当前战斗，脱战后立即按Q复活。Q实际发出后原地等待至少11秒，期间不移动、转向、切目标、攻击或吃喝，即使重新进入战斗也不会主动取消读条；11秒后仍在施法则继续等待读条结束。等待结束确认宝宝存活才继续，未复活成功则脱战后间隔2秒核验重试。角色自身复活后的E→Q→11秒→8固定顺序保持不变。

近身协助宝宝：猎人模式或远程模式下，目标明确正在攻击本角色的宠物、近战技能已在射程内且远程技能明确不在射程内时，角色改用1、2近战，角色无需先掉血。距离拉开、条件消失后恢复原技能顺序；已经因角色掉血切换的本场1、2循环仍保留。不会将“目标没有攻击角色”直接推断为攻击宝宝，也不把仅有距离错误当作近身证据。

本机召唤E、复活Q、关闭聊天命令的配置保留。固定流程结束的旧宠物死亡反馈不会立刻重复Q，之后观察到活宠物再死亡仍触发脱战恢复。新版识别自身宠物目标需要在游戏执行 `/reload` 加载0.5.17；旧插件仅缺少这项新识别，客户端会提示，不猜测其他玩家的目标。

0.8.80 修正重启后反复恢复已失效的包满售卖去程：新行程保存自动/手动来源，确认背包已不满且装备可用时取消自动售卖旧去程，保留当前巡航及已录NPC路线。手动任务、已在返程、仍包满、零耐久或状态不明时继续保留断点。插件未变，无需因本次修复重新加载。

0.8.79 修正猎人技能切换与冷却等待。“技能设置”的“猎人”勾选框启用后（旧方案默认不勾选）：

- 仅在战斗中观察到角色生命值实际下降后，放弃本轮剩余技能顺序，循环 `1→2`；怪物以你为目标、靠近、攻击未造成可见掉血或宠物承伤均不触发该切换，脱战后新怪重新使用已填写的技能行。

## 当前功能

| 模块 | 当前行为 |
| --- | --- |
| 巡航与寻怪 | 手动输入或逐点保存当前位置，闭合路线循环；先找附近目标，无目标再接入最近巡航点。目标可在路线附近，击杀后继续附近搜索或返回巡航。 |
| 战斗 | 默认主动寻找黄名怪，可勾选主动攻击红名怪；遇袭优先反击，跳过已被其他玩家占用的目标。确认近战接触后使用技能序列。 |
| 五行技能 | 每只新怪随机选择一条非空技能行，本次战斗循环执行该行，并记录行号；可设置技能间隔，默认 `0.75` 秒，允许 `0.10–5.00` 秒。4/5 终结技失败时先补按 2，再重试原终结技。 |
| 拾取与剥皮 | 脱战稳定至少 `0.5` 秒后按 F 拾取；确认拾取完成后，可用 F 交互剥皮或 7 技能剥皮，在技能设置中选择。受袭时放弃当前尸体任务、优先反击，随后 `60` 秒暂停拾取和剥皮。 |
| 吃喝与潜行 | 食物用 `=`，饮水键可配置；进食后至少等待 `10` 秒并等血量到 `100%`，适用法力恢复到 `99%`。仅启用盗贼恢复且读取到能量资源的近战角色，进食后按 Q 潜行、满血后按 Q 退出；其他角色吃喝不按 Q。盗贼低于 15% 血量尝试 6 消失；未成功脱战继续战斗，脱战后保持潜行原地回血，不吃喝。 |
| 死亡恢复 | 记录死亡坐标，释放灵魂后沿录制的跑尸路线行进，再接近死亡点，核验并点击尸体复活按钮；恢复后继续。 |
| 售卖与修理 | 共用一条录制的 NPC 路线，支持包满触发和手动按钮。实际售卖依赖游戏端已有自动清包功能；通过商店、背包和耐久状态核验结果。售卖窗口分两轮打开，每轮至少等待 3 秒再关闭。 |
| 零耐久修理 | 装备实际耐久为 0 时优先去 NPC，脱战后尝试 Q 潜行，去程不与攻击者缠斗；抵达 NPC 后退出潜行。紧急修理导航不设时间期限，仍保留受阻检测。 |
| NPC 断点 | 保存实际路线、下一未完成路点和行程状态；重启后优先恢复未完成的 NPC 行程。 |
| 运行恢复 | 可启用异常重试和人工操作后的空闲恢复；窗口累计击杀数在同一客户端窗口内累加。`F12` 或停止按钮取消自动运行。 |

### 随机路线

在“随机路线与休息”页启用后，按已录制路线生成变体：

| 用途 | 可选路线总数 | 选择时机 |
| --- | --- | --- |
| 打怪巡航 | 原路线 + 20 条变体，共 21 条 | 启动及每圈完成后随机选择 |
| NPC 往返 | 原路线 + 10 条变体，共 11 条 | 去程、返程选择不同编号；断点恢复保留原选择 |
| 跑尸 | 原路线 + 5 条变体，共 6 条 | 每次启动新的跑尸流程时选择 |

日志显示所选路线编号。变体保留原起终点及转角，在路段内添加有界偏移点，默认最大偏移 `0.06` 个地图坐标点，并受允许偏离范围约束。原路线不被覆盖；未录制的路线不会自动生成。生成文件保存在 `random-routes/`，也可点击“生成并保存随机路线”手动导出。

### 定时休息

启用后，在线累计包含巡航、战斗、恢复、售卖、修理和跑尸。程序生成 100 个不同的额外时长候选，每轮随机选择一个，在线上限为 **2 小时 + 1 秒至 120 分钟**；相邻两轮额外时长不同。停止及中断后的等待不累计在线时间。

到点后先完成当前战斗或跑尸，脱战且非施法时打开 ESC 菜单。确认已回到角色选择界面后，随机休息 **13、15 或 18 分钟**；到时确认进入游戏按钮，再按回车，收到有效的同地图状态后恢复运行。计时与阶段保存到 `quick-session.json`。

菜单识别需要 Windows OCR 语言组件和 `assets/read-menu.ps1`。加载、断线或读取失败不会被视为成功下线；无法确认菜单时等待并记录，不填写账号或密码。操作游戏时需保持游戏窗口在前台。

### 0.8.49 修复

修复“丹莫罗 → 安威玛尔”这类同图子区域名称变化导致录制、导航或恢复误停的问题。现代地图模式 1/2 使用地图编号与坐标模式判断坐标空间，允许非空区域名称变化；旧版模式 3 仍核验名称。不同地图或坐标模式仍不能混录。

NPC 录制错误现在分别说明采样过期、核心读取错误、死亡/灵魂、实际地图变化或坐标越界，已录点保留。

### 0.8.50 当前角色交互按键检查

插件实时读取当前角色的“与目标互动”绑定，支持主、副键位。已确认 `F` 未绑定此动作时，客户端在启动及每次交互按键前明确提示，避免误按“协助目标”后丢失怪物目标。换角色须重新核对；其他角色的配置文件不能代表当前角色的绑定。旧插件没有该字段时仍兼容，但日志会提示更新插件并 `/reload`，不会把未知状态认作检查通过。

### 0.8.51 接近前检查与可选剥皮

新增读取游戏的 `autoInteract`（点击移动）设置；启动时发现关闭会明确提示开启，未知时提示更新插件。此设置和F绑定正确仅证明配置条件，不代表实际接近成功；接近仍依靠游戏交互，不能保证绕过地形障碍。当前角色未配置7号剥皮技能时，本轮跳过剥皮，继续打怪与拾取，不再因此阻止整个启动。

### 0.8.52 近战 / 远程英雄

“技能设置 → 战斗类型”可选择近战英雄或远程英雄，保存在当前方案及录点草稿的 `RangedCombat` 字段；旧配置默认近战。近战保持先接近、确认普攻接触再施放技能。远程每个新目标先用F校正朝向并取消自动移动，随后直接按所选技能行与间隔施放，不等待近战命中，也不因原地施法而执行近战后退换向。远程不会额外发送近战 `/startattack`；技能行中用户自行填写的按键仍会执行，应填写适合当前角色的技能。

远程模式不执行盗贼专用的Q潜行、6消失、9闪避及4/5失败补2规则，包括恢复和零耐久修理的潜行动作。目标身份、死亡、被其他人占有、地图及前台检查继续生效。远程模式允许尝试技能，不把未知射程视为已经进入有效射程；实际施放及命中仍需游戏确认。

远程启动不要求普攻命中事件，也不会仅因点击移动关闭而拒绝施放远程技能；关闭时会提示尸体接近拾取仍需核对。

### 0.8.53 无食物启动与自然恢复

食物库存为零时允许启动，低血量时取消移动、原地自然恢复，不反复按空食物栏。法力角色未配置饮水键时自然回蓝；自然恢复不受原有60秒食物超时限制，每30秒记录恢复进度。仍须至少等待10秒、生命100%及适用法力99%才继续；受袭优先反击，状态不可读时不假定已经恢复。

### 0.8.54 远程接近与自动射击

配套插件逐个读取当前动作栏1–4的射程、技能类型和自动射击开启状态。远程模式选用技能行中第一个可识别的远程技能判断距离：射程外保留F交互接近，进入射程后停止移动；不再刚按F就取消接近。目标再次移出射程时重新接近，仍受原有路线追击范围和超时约束。F实际接近依赖游戏交互设置，未知射程不认定已经到位。

已开启的自动射击不重复切换；已知射程外、不可用或冷却中的1–4号动作跳过。识别为近战的动作在有近战距离或原有接触证据后使用，避免远处混按近战打断射击。5–0、-、=仍沿用配置执行，未增加其逐键距离回读；宏和无法识别的动作类型仍可能需要用户核对。更新客户端与插件后须在游戏执行一次`/reload`；旧插件没有这些数据，不能获得完整修复效果。

0.8.55曾增加无位移时短按W的补偿；实机反馈方向不对后已在0.8.58移除。F绑定及点击移动设置正确不代表角色已经面向目标，不能据此直接前进。

0.8.56取消“追怪总计12秒就放弃”的判断，改为持续无位移12秒才放弃；有位移时可继续接近。仍保留配置的追怪范围和单次脱战追击45秒上限。45秒仍未接触目标时返回巡航找下一只，不终止整轮固定路线任务。日志区分无位移、范围边界和总时限，便于核对原因。

### 0.8.67–0.8.68 交互接近与越界返回

恢复巡航中Tab选怪、开启普攻、F交互接近、接触后执行技能、死亡后拾取的流程。F之后记录实际朝向和坐标变化。撤回0.8.58的画面血条右键接近以及0.8.61–0.8.63本机测试中的血条居中转向和前进补偿：画面中的目标方向不能直接当作角色朝向。

本机近战测试观察到F在距怪约20–25码时停止，临时卸下远程武器后仍出现。0.8.67取消0.8.65的试转向：仅在同一目标的F交互期间观察到实际位移后，记录该次接近朝向；后续F停步且角色仍保持该朝向时，按↑700毫秒补足近战距离。没有该目标的实际接近记录、朝向改变、换目标、状态不可读或进入战斗时不授权继续。该机制不补充弹药，缺弹药时远程射击仍不能通过验收。

已确认近战接触后，不再因暂时没有成功施法而后退转向；冷却/资源等待保留。失焦日志附加当时前台窗口，便于核对外部中断。

0.8.67同时取消接触确认前已经排队的战斗脱困动作，避免刚开始互相攻击又后退、转向和跑开。

0.8.68处理接近过程中单次移动跨过追怪边界的情况：脱战且当前位置、朝向和地图有效时，放弃当前目标，返回最近巡航点后继续找怪，不结束整轮；回归途中不主动接新目标，被攻击时仍优先防御。死亡、地图变化和状态不可读仍交由相应恢复流程处理。

0.8.69同时记住多只近期接近失败的目标，30秒内不重复主动追击，避免两只失败目标交替出现时不断打断巡航；战斗中的攻击者不受这个等待限制，期满后允许重新尝试。

当前游戏按键设置显示前进绑定↑、W未绑定，因此快速客户端的巡航、NPC路线、跑尸、脱困和停止移动统一使用↑；F交互接近由游戏处理，其他电脑须核对实际绑定及点击移动设置。本版未增加键位自动识别。血条候选工具仅保留作诊断，未测量受限制的姓名板；原有血量识别保留。不能将按键发送成功当作角色移动或击杀成功，连续实测结果见开发进度。

## 快速开始

1. 将 [addon/WoWProbe](addon/WoWProbe) 放入实际游戏客户端的 `Interface/AddOns/`，启用插件；更新插件后重新加载游戏界面。保持窗口化显示，露出左上角状态色块。
2. 打开 `WoWProbe.exe` 或“启动自动打怪.cmd”。本机安装位置为 `E:\WOW\新版测试\WoWProbe.exe`；源码构建输出在 `bin/WoWProbe.exe`。其他电脑可使用自己的部署目录。
3. 在“固定巡航点”页，依次走到各位置点击“保存当前巡航点”，最后“闭合到起点”，例如 `A → B → C → D → A`；也可载入已有 JSON。核对当前地图、移动参数和技能键位。
4. 在“技能设置”选择近战或远程英雄，填写五行中的至少一行和技能间隔；留空行不参与随机选择。按需要设置红名怪、无聊天战斗及恢复选项。
5. 在“自动售卖”或“自动修理”页，从当前地图上选定的起点开始录制，绕过障碍走到 NPC 旁，再结束录制。两页共用路线，录制一次即可；确认并启用所需功能。
6. 在“跑尸路线”页，从墓地沿可通行路径录到打怪区。存活或灵魂状态均可录制，途中复活也可继续。换地图后应重新核对对应路线。
7. 配置“随机路线与休息”，保存方案，点击“开始自动打怪”。先短程检查战斗、恢复和往返，再验收完整流程。

### 需要核对的游戏按键

| 按键 | 当前用途 |
| --- | --- |
| `Tab` / `F` | 选敌 / 交互、接近目标及拾取，需匹配实际游戏绑定 |
| `↑` / `←` / `→` | 前进 / 左转 / 右转；快速客户端统一使用方向键，W不再作为前进键 |
| `7` | 剥皮技能；未配置时取消客户端的剥皮选项 |
| `=` | 食物，放在主动作条第 12 格；饮水使用恢复设置中的按键 |
| `Q` / `6` | 当前盗贼方案的潜行 / 消失，需匹配实际角色与绑定 |
| `1` / `F8` / `F9` | 无聊天战斗模式的默认开始攻击 / 上一个目标 / 停止攻击键，可在界面修改 |
| `F12` | 停止自动运行并取消自动恢复 |

0.8.72 增加同一尸体的 F 拾取重试：尚未看到拾取窗口开启事件时，间隔至少1.5秒再按F，总计最多3次，仍保留5秒未确认截止；一旦窗口已开启、目标变更、受袭、正在施法或确认尸体无可拾取物，不发送重试。成功计数仍以窗口开启与关闭事件为准。

0.8.71 补充尸体重选诊断：F 是与当前目标交互，F8 是默认的“选中上一个目标”，两者必须分别配置。怪死亡后目标会被清除，F8 未能选回同一尸体时，客户端不会向空目标发送 F。设置时不要选“上一个敌人目标”。失败日志会显示实际配置的重选键；这只是诊断改进，不能代替游戏内绑定。

启用无聊天战斗模式前，开始攻击键需绑定 `/startattack` 宏，停止攻击键需绑定 `/stopattack` 宏，上一个目标键需绑定游戏的“选中上一个目标”。该选项作用于战斗、拾取和剥皮，不代表所有 NPC 操作都不使用聊天命令。

0.8.70 新建方案界面默认勾选无聊天战斗和 F 交互剥皮。已有方案保留其选择；缺少 `SkinWithInteract` 字段的旧 JSON 继续采用 7 键。宏在游戏宏界面配置一次，运行时由按键触发，客户端不逐次打开聊天框输入。无聊天重选尸体只发送一次上一个目标键，核验身份失败就跳过，不退回按名字输入命令，也不反复切换 F8。F 交互剥皮不要求动作栏 7 已放剥皮，但角色仍须具备剥皮技能及所需工具；只有收到剥皮成功事件才计数。NPC 断点恢复继承当前的无聊天和剥皮选择。

本机本次已启用这两项；首次启动因游戏 `autoInteract=0` 被接近检查阻止。F 当前绑定正确，但 1/F8/F9 的游戏内宏与绑定尚未重新确认；0.8.70 的击杀、拾取及 F 剥皮完整实机验收尚未通过。

## 构建与验证

在 Windows 上使用系统 .NET Framework 编译器构建，无需 NuGet。源码入口见 [src/Program.cs](src/Program.cs)，版本定义见 [src/AssemblyInfo.cs](src/AssemblyInfo.cs)。

```powershell
# 编译并运行当前客户端针对性检查（含界面配置检查）
.\build.ps1 -QuickCheck

# 完整 C# 构建与底层测试
.\build.ps1

# 构建并打包
.\build.ps1 -Package

# C#、Lua 5.1、跨语言协议检查；此命令跳过桌面烟测
.\verify.ps1 -PythonPath "C:\path\to\python.exe" -SkipDesktopSmoke
```

验证脚本需要可用的 Python 和 `lupa.lua51` 测试依赖；游戏电脑运行客户端不需要这些开发依赖。去掉 `-SkipDesktopSmoke` 可执行桌面及当前客户端界面检查。构建脚本输出 `bin/WoWProbe.exe`；打包输出 `dist/WoWProbe-Current.zip` 和 SHA256 校验文件，完整解压后使用，不要只复制 EXE 而遗漏 `assets/` 等文件。
